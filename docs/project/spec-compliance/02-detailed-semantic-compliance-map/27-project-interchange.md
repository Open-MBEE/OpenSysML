| Semantic Rule | Implementation | Test Case | Status |
|--------------|----------------|-----------|--------|
| A project interchange archive is a ZIP of a project directory with `.project.json` and `.meta.json` at its top level; its model files may lie in subdirectories, and the project's namespace is flat across them (§10.3) | `project/archive.go` `ParseArchive` (read in memory through `archive/zip`; member paths relative and free of `.`/`..`, each once; both files required at the top level, a nested pair reported as a folder holding the project), `Archive.Files`, `MemberPath`/`SplitMemberPath` (members named `<archive>.kpar/<member>`); `project/read.go` `ReadFile` (a member read from its archive); `project/project.go` `Discovery.archiveFiles`, `expandPattern`; `project/discovery.go` `installedProjects` (an archive under a root is an installed project), `used`; `project/deps.go` `summarizeArchive`; `libs/archive_source.go` `NewArchiveSource`, `archiveSource.TierOf` (the library tier from the project's name); `lsp/files.go` (members indexed from the archive) | `project/archive_test.go` `TestParseArchiveReadsAValidArchive`, `TestParseArchiveRejectsMalformedArchives`, `TestReadFileReportsAMalformedArchiveOnItsPath`; `tests/kpar` `TestOMGArchivesAreValidProjectInterchangeArchives`, `TestOMGArchivesIndexTheBundledLibrary` (the OMG release archives yield the qualified names and tiers of the embedded release), `TestArchiveNamedAsInputLoadsItsFiles`, `TestSysandProjectLoadsItsInstalledArchives`, `TestArchiveUnderLibraryRootAnswersAnImport`, `TestMalformedArchiveUnderLibraryRootIsAWarning`; `lsp/archive_test.go` | ✅ Faithful |
| `.project.json` (Table 12): `name` and `version` are mandatory, `description`, `license`, `maintainer`, `website`, `topic` and `usage` optional, each usage with a mandatory `resource` IRI and an optional `versionConstraint` — a string whose syntax the specification does not define; OpenSysML reads it as an npm-style semver range (`project/constraint.go`); the `resource` IRI is matched to an installed project by its last two path segments, a version-control repository read from the ECMA-427 package URL `pkg:generic/<name>?vcs_url=<vcs>+<transport>://<host>/<path>[@<version>][#<subpath>]` (qualifier percent-encoded), its `pkg:git/<host>/<path>` alias or the bare `<vcs>+<transport>://` URL alike | `project/interchange.go` `parseInterchange` (field presence and types; an unknown property is kept, not refused, since the table is open to extension), `Usage.location` (the decoded `vcs_url`), `resourceSegments`, `resourceVersion`, `Interchange.Uses`; `project/discovery.go` `malformedResource` (a `vcs_url` that is no repository URL) | `project/archive_test.go` `TestParseArchiveRejectsMalformedArchives` (no name, no version, a name of the wrong type, a usage without a resource), `project/interchange_test.go`, `project/ecma427_test.go`; `tests/kpar` `TestSysPIProjectResolvesItsImportFromLib`, `TestEverySpellingOfTheRepositoryLinksTheSameProject`, `TestASubpathInTheVCSURLNamesTheSubPackage`, `TestAMalformedVCSURLIsAWarningAndLinksNothing` | ✅ Faithful |
| `.meta.json` (Table 13): `index` (root namespace to file) and `created` are mandatory; `metamodel` is an IRI; a `checksum` per file names a value and an algorithm of the schema's list — one object per file in the normative `Meta` schema (`KerML-Model-Interchange.json`), which every producer writes, a list of one or more in the table's text; `NONE` is not among the schema's algorithms but is what sysand records for a file it did not digest | `project/archive.go` `Checksums` (one object or a non-empty list, read either way, one written as the schema's object), `Checksum.Unrecorded` (algorithm `NONE`, or an empty value: no digest recorded), `ParseMeta`, `Archive.readMeta` (the index and every checksum must name a member), `Archive.verify` (every recorded checksum of an algorithm this build computes — SHA-1/224/256/384/512, SHA3, MD5, Adler-32 — is verified; one of the schema's other algorithms is noted as unverified; one outside the schema is refused; an unrecorded one is neither verified nor refused) | `project/archive_test.go` `TestParseArchiveRejectsMalformedArchives` (no index, no created, an index or checksum naming a missing member, a wrong checksum, an algorithm outside the schema, a metamodel that is not an IRI), `TestParseMetaReadsBothChecksumShapes`, `TestChecksumsMarshalAsTheSchemaObject`, `TestParseArchiveSkipsAnUnrecordedChecksum`, `TestParseArchiveNotesAChecksumItCannotCompute`; `tests/kpar` `TestSysandInstalledDirectoryReadsAsAnArchive` (sysand's `.meta.json`, zipped), `TestSysmodMetaWithUnrecordedChecksumsReads` (MBSE4U sysmod-sysmlv2 5.1.5) | ✅ Faithful |
| Writing an archive: the directory's files, sorted, with `.meta.json` kept when present and generated (index, SHA256 checksums, creation time) when absent; reading one back reproduces the directory | `project/bundle.go` `Bundle` (fixed timestamps, so two runs are byte-identical; the result is parsed before it is returned), `generateMeta`, `Unbundle` (into a new or empty directory only; files created exclusively, parents checked against the directory); `cmd/sysml/bundle.go` `runBundle`, `runUnbundle` | `project/bundle_test.go`; `tests/kpar` `TestBundleIsDeterministicAndUnbundleReproducesTheRecordedFiles` (the CLI: two runs identical, the unbundled directory identical to the source, an archive sysand wrote re-bundled and validated) | ✅ Faithful (§10.3 states the archive's content, not how a tool writes it; the fixed timestamp and sorted order are this tool's determinism) |
