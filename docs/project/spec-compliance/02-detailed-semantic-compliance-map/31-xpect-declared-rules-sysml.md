### Validation Rules Declared by the Reference's Own Xpect Suites — SysML half

The SysML families the pinned reference (pilot `2026-09`) declares in
`build/pilot-xpect-corpus/sysml/…/tests/validation/invalid/` and we reported nowhere. Each row
is keyed to the SysML v2.1 Beta 2 / KerML 1.1 Beta 2 §8.3 constraint name, with the reference's
validator name (`SysMLValidator` / `KerMLValidator`) second where it differs and *pilot-only
check* where the Beta 2 text states no such constraint; the Beta 2 text and the validator
source were read before implementing, and the row's scope and exemptions — not its message —
decide its status. The last two rows are Beta 2 constraints the notation satisfies by
construction, so neither validator ever reports them. Every rule is at the constraint or type tier and
none double-reports what a lower tier already errored on. Re-measured on the tree merged with
the sibling declared-rule work: Xpect 599 → 629 agreeing rows, 0 rows newly disagreeing; the differential
(125 only ours, 137 only the pilot's) and the rejection corpus (26 both reject) unchanged. Those
three figures are as measured at that round and are not the current baseline, which the generated
block in [README](../../README.md) and [architecture](../internals/architecture.md) states.
