### State Activity (`OpenSysML Libraries/StateActivity.kerml`; an OpenSysML extension, non-normative)

SysML v2 gives a model no Boolean reading whether a state usage is active. `States.sysml`
declares `StateAction`, `stateActions` and `substates`, `StatePerformances.kerml` declares
`StatePerformance` with its `start`, `done` and `substatePerformances`, and none of them is a
Boolean an expression can test — `fill.done` and `fill.start` are occurrences, the state's end
and start — so under the pinned pilot `fill.isActive` is `Couldn't resolve reference to Feature
'isActive'`. OpenSysML declares one in a clearly non-normative extension library a model must
import: `library package StateActivity { derived feature isActive : Boolean[1] featured by
States::StateAction; }`, bundled under the same `embed.FS` and gates as `OpenSysMLMathFunctions`,
with the vendored OMG files untouched. A chain member the operand's own and inherited members do
not declare resolves to a feature visible where the chain is written — so brought in by an import
— that is `featured by` a type the operand conforms to (KerML 7.3.4.3 feature typing and
featuring), which is what makes `fill.isActive` resolve under the import and nothing else.
Without the import it stays `unresolved member: isActive`, as before; the import itself is
`nonstandard-notation`, an error under strict conformance, so a conforming model is untouched.
None of this is spec compliance.
