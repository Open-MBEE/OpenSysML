## Model Context Protocol Server (`internal/frontend/mcp`, `cmd/sysml-mcp`)

**Standard:** Model Context Protocol, revisions 2025-06-18 through 2026-07-28 (the SDK, `modelcontextprotocol/go-sdk` v1.8.0, negotiates any of them and the authorization clauses below are the same in each): *Transports* § Streamable HTTP, Security Warning; *Authorization* § Protocol Requirements, § Authorization Server Discovery, § Access Token Usage, § Error Handling, § Security Considerations; RFC 6750 (bearer token usage), RFC 9728 (protected resource metadata). **Reference:** [docs/reference/sysml-mcp.md § Transports](../reference/sysml-mcp.md#transports).

| Rule | Implementation (file:function) | Tests | Status |
|---|---|---|---|
| *Transports* § Security Warning 1: the server validates the `Origin` header of every connection and refuses an invalid one with 403, against DNS rebinding | `internal/frontend/mcp/http.go` `OriginPolicy.Allows`, `OriginPolicy.Handler` (no `Origin`, a loopback origin, or one named by `-allow-origin`; the wildcard is refused) | `internal/frontend/mcp/http_test.go:TestOriginPolicyAllows`, `:TestOriginPolicyHandler`, `:TestOriginPolicyHandlerGrantsCORSByName`, `cmd/sysml-mcp/http_test.go:TestTheHTTPTransportRefusesUnknownOrigins` | ✅ Faithful |
| *Transports* § Security Warning 2: a local server binds loopback rather than every interface | `cmd/sysml-mcp/transport.go` `httpAddress` (a port alone or an address with no host binds `localhost`) | `cmd/sysml-mcp/main_test.go:TestHTTPAddress` | ✅ Faithful |
| *Transports* § Security Warning 3 and *Authorization* § Protocol Requirements: an HTTP server authenticates its connections, as an OAuth 2.1 resource server; the stdio transport does not use HTTP authorization | `internal/frontend/mcp/auth.go` `BearerToken.Handler`; `internal/frontend/mcp/service.go` `ServeHTTP` (refuses a listener other machines reach with no token, `ErrNoToken`); `cmd/sysml-mcp/main.go` `serve` (the same refusal, exit status 2, naming `-token-file`, `-token` and `OPENSYSML_MCP_TOKEN`); `cmd/sysml-mcp/transport.go` `readToken` | `internal/frontend/mcp/http_test.go:TestServeStreamableHTTPRefusesOffLoopbackWithoutAToken`, `internal/frontend/mcp/auth_test.go:TestServeStreamableHTTPEnforcesTheTokenOnLoopback`, `cmd/sysml-mcp/http_test.go:TestTheHTTPTransportRefusesOffLoopbackWithoutAToken`, `:TestTheHTTPTransportRequiresTheToken`, `:TestTheHTTPTransportReadsTheTokenFromTheEnvironment`, `cmd/sysml-mcp/main_test.go:TestReadToken`, `:TestCommandLine` | ✅ Faithful for the resource-server role, in its minimal form: one bearer token issued out of band by the operator; a loopback bind with no token is served unauthenticated, which the warning permits for a local server (it is a SHOULD) and the stdio transport's trust model already grants |
| *Authorization* § Access Token Usage, Token Requirements: the token is carried in the `Authorization` request header as RFC 6750 § 2.1 spells it, on every request, never in the query string | `internal/frontend/mcp/auth.go` `BearerToken.Handler` (reads the header only; the scheme is case-insensitive), `guard/token.go` `IsB64Token` (RFC 6750 `b64token` syntax, checked at startup by `NewBearerToken` so the server is never given a token a client cannot send) | `internal/frontend/mcp/auth_test.go:TestNewBearerToken`, `:TestBearerTokenHandler` | ✅ Faithful |
| *Authorization* § Access Token Usage, Token Handling, and § Error Handling: every token is validated before the request is served; an invalid or missing one is answered 401, a malformed authorization request 400; the comparison does not leak the token by timing | `guard/token.go` `Token.Matches` (`crypto/subtle.ConstantTimeCompare`), `BearerToken.challenge` (401 with `error="invalid_token"` for a wrong token, 401 with no error code when no credentials were sent, 401 `invalid_request` for another scheme, 400 `invalid_request` for a malformed `Bearer` header, as RFC 6750 § 3.1) | `internal/frontend/mcp/auth_test.go:TestBearerTokenHandler`, `cmd/sysml-mcp/http_test.go:TestTheHTTPTransportRequiresTheToken` | ✅ Faithful — audience binding (RFC 8707) is trivially satisfied: the token is issued for this server alone and accepted by nothing else |

| *Authorization* § Security Considerations, Token Theft and Communication Security: the token is stored and handled securely, is not written where it can be read back, and travels over TLS | `cmd/sysml-mcp/transport.go` `readToken` (`-token-file` keeps it out of the process list; `OPENSYSML_MCP_TOKEN` out of the command line); `internal/frontend/mcp/service.go` `ServeHTTP` logs `auth=bearer`, never the token; `internal/frontend/mcp/auth.go` `challenge` never repeats what was sent; `-tls-cert`/`-tls-key` serve TLS 1.2 or later, and a token served in cleartext off loopback is logged as a warning | `cmd/sysml-mcp/http_test.go:TestTheHTTPTransportRequiresTheToken` (log and refusal checked for the token), `:TestTheHTTPTransportServesTLS`, `internal/frontend/mcp/http_test.go:TestServeStreamableHTTPWarnsOfATokenOverCleartext`, `internal/frontend/mcp/auth_test.go:TestBearerTokenHandler` | ⚠️ Approximate — TLS is not forced beside a token: the server may sit behind a TLS-terminating proxy (`-public-url` names the URL the proxy serves), where cleartext between the two is the deployment's choice and is warned about rather than refused; the `-print-config` block writes the token in clear, which the usage and the reference say to keep out of version control |
