- `%check` and `%explain` now fix a literal value bound with `=` (`attribute limit : Real = 1.0;`) as declared, since the feature holds it at all times (KerML 1.1 §7.3.4.5), and assert the defining equation of a derived value (`attribute y : Real = x * 2.0;`) on a constraint or requirement as they did on a part, an equation a redefinition supplies for an inherited feature included; a `default` or `:=` value stays free, as before. `BoundLiteral::bound` and `CheckDerived::k`, `r`, `r2` and `p::c` answer `unsat` rather than a witness breaking the declared value. `solve.Pin` carries `Bound` and `runtime.EffectiveFeature` has `Binds`, read from the declaration that wrote the value. A feature a constraint declares under the same name as one of its owner's is fixed on its own rather than dropped for the owner's: `solve.FixedFor` tells features apart by declaration and redefinition, not by name, and reads an object only for the features of its own type, so `%solve` over an object of the part fixes the constraint's feature as declared rather than to the value the object holds under that name.
