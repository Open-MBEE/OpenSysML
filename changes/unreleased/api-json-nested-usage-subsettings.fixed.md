- A nested usage's implied subsetting now reaches the RDF and API JSON element forms: a composite part in a part definition or usage is one of `Items::Item::subparts`, an item one of `subitems`, a performed action one of `Parts::Part::performedActions`, and so on through the SysML v2 §8.3.6.4 `check*Specialization` rules, judged for a graph element by its metaclass, its owning type's metaclass, `isComposite` and `portionKind`. The nesting feature's members join the usage's completed `inheritedMembership`, `inheritedFeature`, `feature`, `featureMembership`, `member`, `membership`, `usage` and the directed projections, and its stubs join the Turtle form and the compact form's `libraryReferences`; before, only the usage's kind base contributed, so a `perform action` or `exhibit state` in a part inherited nothing.
