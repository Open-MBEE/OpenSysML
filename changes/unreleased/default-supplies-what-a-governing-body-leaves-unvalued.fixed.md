- Instantiating a `ShapeItems::RightCircularCone` or `RightCircularCylinder` no longer reports `xoffset.dimensions: no value for feature mRef` or `edges.length: no value for feature Circle::radius`. A body valuing one feature of a redefined attribute (`:>> xoffset { :>> num = 0; }`) governs over the inherited `default` only for that feature, so the default supplies the rest (`mRef`) — also when the redefined declaration is a package-level attribute, as the Geometry library writes its offsets — and a `ScalarQuantityValue` object stating its `num` and `mRef` reads as that quantity (`0 [m]`). The materialization sweep passes over a derived value whose derivation reads a feature nothing gives a value to, as it passes over the unvalued feature itself; the read still reports the typed no-value error. The cone's and cylinder's base circle radius is one such feature: the library binds the semi-axes from the radius, never the radius from them (`docs/project/omg-issues.md`).
