- Instantiating a `ShapeItems::RightCircularCone` or `RightCircularCylinder` no longer reports `xoffset.dimensions: no value for feature mRef` or `edges.length: no value for feature Circle::radius`. A body valuing one feature of a redefined attribute (`:>> xoffset { :>> num = 0; }`) governs over the inherited `default` only for that feature, so the default supplies the rest (`mRef`) — also when the redefined declaration is a package-level attribute, as the Geometry library writes its offsets — and a `ScalarQuantityValue` object stating its `num` and `mRef` reads as that quantity (`0 [m]`). The cone's and cylinder's base circle radius is a feature the library gives no value — it binds the semi-axes from the radius, never the radius from them (`docs/project/omg-issues.md`) — so the check passes over the edge length derived from it as it passes over any unset feature, and reading it is the typed no-value error naming `Circle::radius`.
