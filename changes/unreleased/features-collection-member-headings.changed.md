- `%features` heads each object of a multi-valued feature with its place in the collection (the index an object path such as `system.slots[2]` reaches it by) and the object it is, and lists that object's features beneath the heading: under `slots = [Instance(ID: 2), Instance(ID: 3)]` come `[1] Instance(ID: 2)` and `[2] Instance(ID: 3)`, each followed by its own features one level deeper. Before, the members' features followed one another at one indentation with nothing saying where one object ended and the next began. The occurrences of a behavior performed several times (`perform action run : Run [2]`) are headed the same way under its row. A single-valued feature is listed as before, since its row already names its object; a heading takes a line of the listing's default 200-line bound and is written only where a line is left for the object beneath it. The same listing is what the Jupyter kernel and the debugger API's `Features` return; the `json` form is unchanged.
