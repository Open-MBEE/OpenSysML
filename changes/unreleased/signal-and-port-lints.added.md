- **Two lints: `undeclared-signal` and `port-type-mismatch`.** A `when <name>` or `defer <name>` whose name matches no declaration in scope and no signal the model sends is reported with did-you-mean suggestions (a send counts the signal its message is typed by, as the runtime names it: a definition through any alias, a feature's value type rather than the feature's name, and the written message before the body's `payload`; a send invoking a calculation counts the type of the value it sends, not the calculation's name, and a literal or computed scalar counts its scalar type, `String`, `Integer`, `Real` or `Boolean`, as the runtime names it), and a `connect`, interface usage or `flow` between ports whose definitions are unrelated and not conjugate-compatible is reported, a port that redefines another taking its type, whether the definitions are parsed or held as interface records, where both were accepted silently. Both are warnings in every mode, `-strict` included; switch one off with `-disable-lint <code>`, `%lint <code> off` or the `disabledLints` editor setting.
