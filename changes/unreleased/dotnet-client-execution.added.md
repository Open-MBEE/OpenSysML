- The .NET client runs and checks behavior. `Model.ExecuteActionAsync` and `ExecuteStateAsync` run an action or a state machine once, with inputs, events and `RunOptions` (schedule, performer, state-run trace, advance, seed, draw policy, clock step), and answer an `ActionRun` or `StateRun` with outputs, performer attributes, final context, diagnostics, the final clock, order dependence and the run's trace. `ExploreActionAsync` and `ExploreStateAsync` run every order of a behavior's choice points within a budget and answer an `Exploration` of distinct `Outcome`s and how it ended. `CheckActionAsync` and `CheckStateAsync` search every schedule for violated properties, deadlocks, failures and divergent features (`CheckOptions`), and answer a `CheckResult` whose violations, divergences and finals each carry a replayable `CheckWitness`, with the answering engine's `Standing`. A failed run is an `ExecutionException` keeping its clock and trace, and a check refused in the answer a `CheckException` keeping the partial result, even when no verdict was supplied. A check answer containing neither a verdict nor an error is rejected as malformed with `TransportException`. Trace records are read into the new `DocumentValue` family (`DocumentEvent`, `DocumentObject`, `DocumentVerdict`, `DocumentState`). Options needing a capability the service lacks are refused before anything is sent, a run and an exploration refuse each other's schedule, and the conformance runner now covers ExecuteAction, ExecuteState and CheckBehavior through this API.
