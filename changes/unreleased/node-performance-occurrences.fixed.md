- **Each performance of an action node is an occurrence of its own.** Where an object performs an action (`part plant { perform action run { action one { out v : Integer; … } } }`), every performance of a named node of the action is now an object held under the node's feature on the performance around it, begun and ended with the performance and holding what its parameters and attributes hold: `plant.run.one.v` reads the value the performance wrote, where it read as undetermined before. A node performed again — reached again through a merge — is a second object after the first, so `run.one` lists every performance in the order they began and `run.one.v` every value; a node typed by an action performs it as that one object, so the callee's own nodes are read through it (`run.call.inner.v`); a node the flow never reaches is held as an occurrence that has not begun, no longer as one alive since the action began, so it is no predecessor or successor of anything. A write to such an object reaches the performance it is. An action definition run by no object holds its nodes' performances the same way from the moment `this` first denotes it (`this.one.v`). The nodes of an `if` branch or of a loop body declared without a body action are still held by no object: the block they belong to is not one yet. Traces of actions an object performs gain a `materialize:` line per node performance, and the identities of objects made after them shift accordingly.
