- **Each performance of an action node is an occurrence of its own.** Where an object performs an action (`part plant { perform action run { action one { out v : Integer; … } } }`), every performance of a named node of the action is now an object held under the node's feature on the performance around it, begun and ended with the performance and holding what its parameters and attributes hold: `plant.run.one.v` reads the value the performance wrote, where it read as undetermined before. A node performed again — reached again through a merge — is a second object after the first, so `run.one` lists every performance in the order they began and `run.one.v` every value; a node typed by an action performs it as that one object, so the callee's own nodes are read through it (`run.call.inner.v`); a node the flow never reaches is held as an occurrence that has not begun, no longer as one alive since the action began, so it is no predecessor or successor of anything. A write to such an object reaches the performance it is. An action definition run by no object holds its nodes' performances the same way from the moment it becomes an occurrence (`this` first denotes it, it reaches a loop, or it sends with no stated sender) (`this.one.v`): the performances under way and the latest ended one of each node, not the earlier ended ones of a node performed again before that. A performance a `terminate` around it drops ends with it. A loop a node reaches is held under that node's performance (`run.stage.loops`), and a node an iteration of a loop performs under that iteration's `body`, whether or not the loop declares a body action (`run.loops#(1).body.add.w`). The nodes of an `if` branch are still held by no object: the branch they belong to is not one. Traces of actions an object performs gain a `materialize:` line per node performance, and the identities of objects made after them shift accordingly.
