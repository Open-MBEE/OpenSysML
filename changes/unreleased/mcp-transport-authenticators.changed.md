- `sysml-mcp -http` declares and resolves its credentials through the reading of `-token-file`, `-token` and `OPENSYSML_MCP_TOKEN` that `sysml-grpc` uses, so an authenticator added to it serves both commands, and verifies each request through the chain it yields: a credential that has expired is answered `401` with `error="invalid_token"`, one that cannot be verified for now `503` with a challenge carrying no `error`, and the protected resource metadata lists the authorization servers and scopes the authenticators advertise. With the one static token the statuses, challenges, metadata, `-public-url` and the loopback rule are unchanged; the help text of `-token-file` and `-token` now reads the same in both commands.
