- **Migration writes UML parameter sets.** A behavior's or operation's `ownedParameterSet` is written `ref set { ref [m] = p; … }` inside its definition, one unnamed reference usage per bound parameter carrying the parameter's own multiplicity; a set's condition has no target and is reported unmapped, and a set binding no written parameter is unmapped.
- **Migrated owned rules are asserted.** A classifier, activity or operation rule is now written `assert constraint N { expr }` rather than `constraint N { expr }`, so the runtime requires it, as a UML invariant means.
- **Migration reads `uml:Expression` else guards.** A guard specification that is an `Expression` with symbol `else` and no operands is written as the else succession of a decision or the unguarded branch of a choice, like the opaque and literal spellings.
- **Expression trees read `xor` and `implies`.** A UML Expression tree symbol `xor` or `implies` over Boolean operands is written as the KerML connective of the same name; over other operands it is refused as a type error, where the operator used to be refused as unknown.
- **`ref` declarations may omit their name.** `ref [1] = x;`, `ref = x;`, `ref [1];` and `ref;` now parse as anonymous reference usages, matching the pilot grammar's optional identification.
