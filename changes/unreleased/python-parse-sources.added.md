- **The Python client parses a model of several documents.** `Connection.parse_sources` and `opensysml.parse_sources` wrap the service's `ParseSources` RPC (capability `parse_sources`): each document is a path the service reads, a `(name, text)` pair of inline source or a `SourceDocument` (also how inline content is declared KerML), an import from one document into another resolves, and each diagnostic names the document it came from. The `Model` returned is the one `load` returns, with `strict` and `strict_conformance` as `loads` has them; it gains `roots`, one root per document, and `documents`, their names, and `find`/`model[...]` search every root, as `opensysml.generate.generate_source` renders every root's definitions. Until now a multi-file model was loaded from Python by concatenating the files into one `loads` call, which lost the names and positions its diagnostics reported.
