- **A cast at the head of a feature chain is judged for conformance.** `(theView as SysML::ViewUsage).exposedElement` — a cast whose result is then chained into, as every viewpoint constraint of the SYSMOD library writes it — drew no `cast-conformance` warning where the bare `theView as SysML::ViewUsage` did, so the pilot's `Cast argument should have conforming types` (KerML `validateOperatorExpressionCastConformance`) went unreported at those sites. The head expression of a chain is now checked where it is written, as a constructor or invocation head already was: `Views::View` and the metaclass `SysML::ViewUsage` specialize neither other, so the warning says so (the metaobject of a usage is `theView meta SysML::ViewUsage`), and a chained cast between related types stays silent.
