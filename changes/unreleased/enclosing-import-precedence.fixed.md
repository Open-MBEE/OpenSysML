- A name an enclosing namespace imports is found before a same-named member owned further out: in `package P { part def T; package K { private import Q::*; package N { part v : T; } } }`, `v` is typed by `Q::T`, the nearest namespace making `T` visible, where it was typed by `P::T` and no diagnostic was reported. This holds for a wildcard and a membership import, of either visibility, in a package, a definition, a usage, a state and an action body, at any depth below the import. A member the nearer namespace owns or inherits still comes first, as does an outer member where no namespace between imports the name. The leading segment of a qualified name follows the same order, so a package that imports its own name no longer names itself from inside: in `package V { private import SI::*; enum def Grade { enum high; } attribute g : Grade = V::Grade::high; }` the leading `V` is `SI::V` and the reference is unresolved, as the pilot implementation reports it; write `$::V::Grade::high`, `Grade::high`, or import the units by name.
