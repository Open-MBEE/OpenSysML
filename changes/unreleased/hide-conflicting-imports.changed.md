- **Two imports bringing distinct elements of one name into a namespace now hide both from it.** KerML 7.2.5.4 excludes such memberships from the importing namespace, so an unqualified reference to the name (or short name) is looked up in the enclosing namespaces instead and is an ordinary `unresolved reference` where none has it, in default and strict mode alike, with a hint naming the imports that hide it and the qualified names that reach each; the `Duplicate of imported member name` warning stays on the import and marks the hidden memberships. A namespace re-exporting both imports has no such member, a qualified name into the importing namespace does not reach a hidden one, and a specialization finds none through its general's protected imports. One element reached twice, an owned member of the name, and an inherited member beside an imported one keep resolving as before, and a call still selects among every function imported under its name. Previously the first import's member was bound, as the OMG pilot implementation does.
