- A feature with a feature value, no declared specialization and no direction now specializes the result of its value for every reader, not only for a chain through it (KerML 8.3.3.3.4 `checkFeatureValuationSpecialization`): with `ref part payload = HAPS.payload;`, the body `{ part :>> userAESA; }` redefines the inherited member, `payload` conforms to what `HAPS.payload` conforms to, and an interface record carries the general. A `default` value, a declared type or specialization, an `in`/`out` feature and a `bind` still add no general. A feature's declared types remain those of its declaration, which the value is checked against.
