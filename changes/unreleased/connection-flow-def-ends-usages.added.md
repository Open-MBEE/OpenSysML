- **Connection and flow definition ends must be usages.** SysML v2.1 Beta 2 types `ConnectionDefinition::connectionEnd` and `FlowDefinition::flowEnd` as `Usage`, redefining `associationEnd`, so every end feature of a connection, interface, allocation or flow definition — inherited ones included — is a usage. A definition that inherits a KerML `end feature` from a kernel association (`abstract connection def B :> Links::BinaryLink;`, `abstract flow def F :> Transfers::Transfer;`) is now reported once, at the definition (`connection-def-end-not-usage`, `flow-def-end-not-usage`: `A connection definition end must be a usage.`, `A flow definition end must be a usage.`); owned usage ends that redefine the inherited ones, and definitions specializing `Connections::Connection`, `BinaryConnection`, `Flows::Flow` or `Flows::Message`, stay clean. The rule is ahead of the pinned pilot (2026-08), which predates it.
- **`Flows::Message` and `Flows::messages` have usage ends again.** As published, the base flow definition owns no ends and inherits `Transfer`'s KerML ends, so the rule above would report the standard library itself. The declared errata overlay now carries the repair the pilot applies for OMG issue SYSML21-681 — `Message` owns `end occurrence source`/`target` redefining `Transfer::source`/`target`, `messages` is an action usage owning ends redefining `Message::source`/`target` and `transfers::source`/`target` — on read, with the published file untouched. An erratum's corrected text may now span several lines, keyed to the one published line it replaces.
