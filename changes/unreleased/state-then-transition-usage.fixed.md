- In a state body, a `then x;` written after a state is the `TargetTransitionUsage` the grammar builds (SysML v2.1 §8.2.2.18.1 `StateBodyItem`, §8.2.2.18.3): a `TransitionUsage` the state owns through a `FeatureMembership`, which owns the `SuccessionAsUsage` to its target through an `OwningMembership`, as the pilot exports it. The semantic model, the symbol structure, the query leg, the RDF and API JSON writers and the notation read back agree on this; before, it was reflected and written as a `SuccessionAsUsage` of the state. A transition written with `transition` or `accept` owns its succession the same way, and every transition answers `succession`. A `then x;` after `entry` (`EntryTransitionMember`) and a member-attached `then state s;` (`SourceSuccessionMember`) stay the `SuccessionAsUsage` the state owns (§8.2.2.9.3, §8.3.13.6; KerML 1.1 §8.3.4.5.4). An action body's `then done { … }` is admitted a body, as `TargetSuccession UsageBody` (§8.2.2.17.8) allows; the body a state body's `then` ends in is the transition's `ActionBody`.
