- A port typed `~P` is now typed by the `ConjugatedPortDefinition` `P::'~P'` on every surface, as SysML v2.1 8.3.12.3 states (`ConjugatedPortTyping::conjugatedPortDefinition` redefines `type`): the Symbol type facts and metadata keep the `~` and resolve to the conjugate, the query `type` property, reflective `Feature::type`, `PortUsage::portDefinition` and `ConjugatedPortTyping::type`/`::conjugatedPortDefinition` (previously not derived) name it while `ConjugatedPortTyping::portDefinition` names `P`, the LSP hover shows `: ~P`, and the Turtle `sysml:type` and API JSON `PortUsage.type` agree with the `ConjugatedPortTyping` the export already wrote; the notation reads back `~P` from either form. Before, every one of these but the typing element reported `P`, so a port typed `~P` was indistinguishable from one typed `P`.
