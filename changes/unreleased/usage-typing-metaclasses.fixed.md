- Usage typing now admits every type the SysML v2 metamodel does and refuses what it does not: a `state` takes any Behavior (an action definition included), a `requirement` any RequirementDefinition (a concern or viewpoint definition included), an `action` any Behavior (a constraint or requirement definition included), while an `in`/`out`/`inout attribute` typed by a part, item or occurrence definition is reported as an undirected one is; the one-type rule counts effective types — a declared supertype of another declared type is redundant, so `requirement r : A, B` with `B :> A` has one type, and the kind's implied library base is a type beside a declared one that does not specialize it, so `calc c : CD` with a constraint definition stays reported (#1885).
