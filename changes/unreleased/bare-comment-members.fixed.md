- A `/* … */` comment written where a member may appear — before a declaration, between declarations, before a body's closing brace or at either end of a file — is now an anonymous `Comment` element owned by the enclosing namespace, as the KerML grammar reads it (the `comment` keyword is optional); before, the parser kept it as trivia of the next declaration, so it never reached `%save`'s element form, the RDF and API JSON exports, or a type's `member`/`membership` lists (the standard library's `Occurrences::Occurrence` carries one, which every occurrence-derived type now inherits as the pilot does). The body of a `doc` or `comment` is the comment written right after its head; a second comment before the next declaration is a member of its own rather than replacing the body. Hover and completion documentation still show the comments written above a declaration, and `//` notes stay trivia.
