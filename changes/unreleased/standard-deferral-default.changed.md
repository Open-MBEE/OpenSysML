- **The default SysML v1 migration writes deferred signals in standard SysML v2, as `-strict` does.** A state's `deferrableTrigger` was written as `defer <event>;`, an OpenSysML extension of the notation, unless `-strict` was passed; it is now written in both modes as the standard encoding: an `item` buffer, a do action whose accept loop keeps each occurrence while the state (substates included) is active, and an exit action that sends the kept occurrences back to the object once the state is left, beside the `@MigrationMetadata::DeferredEvent` annotation. `defer` no longer appears in migration output, so a migrated model no longer depends on the extension; the rules the strict encoding followed — an unguarded transition out of the state wins, guarded and substate transitions keep the loop, overlapping deferrals share one loop, an unguarded completion transition drops the deferral as unmapped — hold in both modes, and only a transition the migration writes takes the signal, so in the default mode a transition into a `choice` or `junction` wins over the deferral where `-strict`, refusing the pseudostate, keeps the signal. The ledger notes for a deferred trigger and its signal event name the standard encoding in both modes, and name a transition out of an enclosing state or a sibling region that accepts the deferred signal, which v1's deferral took precedence over and the standard encoding cannot hold the signal back from.
