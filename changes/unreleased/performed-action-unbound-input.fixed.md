- **A performed action's unbound input ends that performance, not its performer's creation.** Materializing a part whose performed action leaves an `in` parameter of a nested step bound by nothing where its effective multiplicity requires a value (`[1..]`; a bare `in` is optional under §7.6.3) no longer fails with `unbound parameter`; the failure is recorded on the performance — ended for good, taking no step and receiving no message — so the object's other features still evaluate. Every other failure of a performed action, and any failure of an explicitly started behavior (`perform obj.beh.start`), still fails as before.
