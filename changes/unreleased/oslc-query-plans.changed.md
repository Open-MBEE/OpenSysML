- **OSLC Query text and the SysML v2 API & Services `Query` are translated into document-query plans** (`internal/doc/querytranslate`) and run by the document-query engine, replacing their two bespoke evaluators. `rdf:type`/`@type` with a metaclass becomes `WhereType`, `sysml:name` `WhereName`, any other property `WhereFeature` with `tolerate=true`, `in [...]` a union of per-value filters, `and` nesting, `oslc.select`/`select` `Project`, `oslc.orderBy`/`orderBy` nested stable `OrderBy`. Consequences on every surface (`-query`, `%query`, `QueryRequest.oslc_query`, `QueryRequest.query`, the MCP `query` tool, every client): values compare by type (`sysx:multiplicityUpper>1` is numeric, as before; so is any numeric attribute of an object row), the property table is the metamodel's read reflectively (`isComposite`, `portionKind`, … are queryable; `satisfiedRequirement` of a `satisfy` is answered as the metamodel derives it) rather than a hand-maintained list, a property the metamodel does not define is a path error naming the nearest spelling, and a failure carries the structured `QueryOutcome` status detail document queries carry. A property OpenSysML derives beyond the metamodel (`multiplicityLower`, `multiplicityUpper`) is now written `sysx:` in OSLC text, not `sysml:`; `sysml:multiplicityUpper` is refused with the `sysx:` spelling named. OSLC `or` is still refused with a typed error.
