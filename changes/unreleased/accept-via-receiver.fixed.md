- An `accept … via <port>` trigger's `AcceptActionUsage` now reflects its receiver: after the payload it owns a receiver parameter (`direction` `in`, through a `ParameterMembership`) whose value is a `FeatureReferenceExpression` to the port, and that expression is the accept's `receiverArgument`, as the RDF/API JSON export and the pilot write them. The accept's `parameter`, `input`, `directedFeature`, `ownedFeature`, `ownedMember`, `member` and `feature` now list its payload and receiver parameters too. This holds in `%eval`, metaobject reads, query cells and gRPC `Evaluate`; before, `receiverArgument` was not derived and the receiver was missing.
