- `sysml -convert api-json` now completes the inherited family of a type whose stated general type is a library type (`attribute q : ScalarValues::Integer`, `part p : Parts::Part`): `inheritedMembership`, `inheritedFeature`, `feature`, `featureMembership`, `member`, `membership`, `directedFeature`, `input`, `output`, `usage` and `directedUsage` were withheld for such an element and now hold the library type's members as KerML 8.3.3.1.10 derives them. `Type::endFeature` is completed too, and an owned end removes the end it redefines by position (KerML 8.3.3.3.4 `checkFeatureEndRedefinition`) from the inherited lists, so a connection usage no longer lists its definition's ends beside its own. An inherited multiplicity or enumerated value is listed in `member`, `membership` and `inheritedMembership` only, no longer in `feature`, `featureMembership` and `inheritedFeature`: neither is held by a `FeatureMembership` (KerML 8.3.3.1.10 `Type::multiplicity`, SysML 8.3.6.5 `VariantMembership`).
- `sysml -convert api-json` and `-convert ttl` now state an accept action's payload parameter with `direction` `in` and list it in the action's `input`; it was stated `out` (KerML 8.3.4.6.4 `parameterDirection`, SysML `validateAcceptActionUsageParameters`). In the element form a subject parameter is an input that redefines the subject of each general of its owner, an objective inherits from the objective it redefines, and an end's inline cross feature is owned through an `OwningMembership` and is not itself an end.
