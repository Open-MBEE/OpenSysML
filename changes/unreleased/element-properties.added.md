- `GetElementProperties` reads the metamodel properties of one element of a parsed model by their KerML 1.1 / SysML 2.1 specification names — `inheritedFeature`, `connectorEnd`, `relatedFeature`, `directedFeature`, `portDefinition`, `payloadType`, `isComposite`, a feature's `value` and the expression's `operand` and `operator`, among the 297 the metamodel evaluator derives — as the model's API element form (`Convert` to `api-json`) spells them, without converting the whole model: an element is named by qualified name, by the positional id of an unnamed member (`Owner::@2`) or by the form's own `@id`, which every element reference in an answer carries — a standard-library element included, read from its own library document's form, so a walk from the model into the library continues; a property the metaclass does not declare, the evaluator could not derive for that element, or OpenSysML does not derive yet, says so instead of answering nothing. Reported as the `element_properties` capability, and reached from the Go client (`Client.ElementProperties`), the Python client (`Model.element_properties`, `Symbol.properties`), the Rust client (`Model::element_properties`) and the Node client (`Model.elementProperties`), with a conformance scenario per protocol. The WASM build does not serve it, as it does not serve `Convert`.
