- A parameter of a behavior or step that has no redefinition clause redefines the parameter at its position in each general behavior or step (KerML 8.4.4.6, SysML 8.3.6.4), and that redefined parameter is now no longer inherited — in name resolution as in the API JSON and RDF element forms (`inheritedMembership`, `inheritedFeature`, `feature`, `featureMembership`, `member`, `membership`, `usage`, `directedUsage`, `directedFeature`, `input`, `output`), in both the semantic model and graph mode, as the pilot implementation resolves and writes it. This changes what a body can name: in `action takePicture : TakePicture { in s; attribute a = scene; }` the general's `scene` is redefined by `s` and no longer resolves, as the pilot reports; with two generals both positions are redefined and neither name is inherited; a position whose directions disagree is a direction violation, not an inherited feature. A `Simulation::MonteCarlo` analysis that lists a statistic as an `out` therefore redefines it by clause — `out N :>> runs;`, `out Deviation : Real[0..1] :>> deviation;` — rather than binding a differently named `out` to it, which the SysML v1 migrator and the Monte Carlo fixtures now write; `return Mean : Real = mean;` is unchanged, a result parameter redefining only a result. A migrated constraint block generalizing another now restates the general's parameters as `in attribute :>> name;` before its own, so those keep resolving in its expressions. A parameter declared without a name at a redefined position answers to the redefined parameter's name (KerML 8.2.4) in its owner's specializations too — among their members, in their shape and at run time — so a check of `ConstraintCheck`, whose `result` the library's `BooleanEvaluation` redefines by an unnamed `return`, still reads `result`; an unnamed member of a library document is of that document's tier.
