- Document prose can be written as AsciiDoc: a KerML textual representation `rep language "asciidoc" /* … */` inside a `Document` or `Section` expands in place into content blocks, and one inside a `part : Paragraph` yields that paragraph, alongside the Markdown form. Paragraphs, admonitions (a strong lead label), bullet and numbered lists, tables of text cells under a header row (static `Table` blocks with `cols` widths), `[stem]` blocks (`Formula`) and block images (`Image`) map onto the existing content kinds; `_emphasis_`, `*strong*`, `` `monospaced` ``, `stem:[…]`, `link:`, URLs, `<<xref>>` and the new `sysml:ref[<target>]` inline macro map onto runs, the reference forms resolved as `Ref::target` is. The body is parsed by Asciidoctor.js run as an external converter — `scripts/asciidoc/asciidoctor-json.js`, provisioned by `scripts/download-doc-pdf-toolchain.sh` and named by `OPENSYSML_ASCIIDOCTOR` — and a missing or failing converter is a typed planning error (`document-plan-markup-tool-missing`, `document-plan-markup-tool-failed`) naming the script and the variable. Constructs no content block renders, `sysml:value[…]` among them, are refused with `document-plan-unsupported-markup-construct` naming the construct and its body line.
