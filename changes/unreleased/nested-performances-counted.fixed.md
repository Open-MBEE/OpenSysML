- A nested `action` or `state` usage declaring no type (`action a1;`, `state s1;`) is a performance object its owner holds before anything performs it, as a typed one (`action a1 : Act;`) already was: one object for a usage declaring no multiplicity, as many as a fixed bound states (`action a[2];`), and none made up for an open bound (`[0..1]`, `[*]`), which keeps the open-multiplicity rule. `p3.a1` reads the object instead of `<undetermined>`.
- The usages count, as listable sequences (`#(i)`, iteration, `includes`) and at model level as on an instantiated object, in the collections the library says they belong to: `ownedActions`, `ownedStates`, `ownedPerformances`, `involvingPerformances`, `suboccurrences` and `timeEnclosedOccurrences` of a part, `ownedPerformances` of an item, `subperformances` and `enclosedPerformances` of an action. The collections of a package-level action usage nothing performs read `<undetermined>`, as the usage itself does.
- The context feature `this` of a performance held under `ownedPerformances` is its owner (a part's or an item's action or state), and of one held under `subperformances` its owner's `this` (Objects.kerml, Performances.kerml), instead of the performance itself. An action nested in an `item` subsets `Objects::Object::ownedPerformances` (KerML `checkStepOwnedPerformanceSpecialization`) rather than only `suboccurrences`.
