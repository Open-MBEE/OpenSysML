- The `smt` engine encodes a feature valued by an expression over other features (`attribute y : Integer = x + 1`) as the interpreter computes it, at every read over the current values: each state defines the feature by its expression and every read within a move substitutes it, through features so valued in turn, so guards, loop conditions, properties, assumptions and results all see the derived value. Such an action was refused (`a feature valued by an expression over other features is computed as it is read`). One whose reads the lowering cannot resolve, one whose declared type narrows its sort, one whose value may be undefined (the interpreter settles it at completion), an assignment to one and a `-check-input` release of one are still refused, each naming its reason; a cycle among such features is refused by the interpreter at the start, before any encoding.
