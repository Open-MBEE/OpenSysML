- State-space dynamics connected by a flow now run together: `flow pusher.push.output to cart.roll.input`, declared by the part performing both actions or by a part owning the parts that perform them, carries the source's `output` into the target's `input` at each step, as a `bind` between the two already did. Before, the target failed with `input of action … is instance, not a vector`.
- An `event occurrence` typed by `StateSpaceRepresentation::ZeroCrossingEventDef` (or a specialization that declares no `guard`) now occurs when a component of the dynamics' derivative changes sign between two steps or arrives at zero, as SysML v2.1 §9.4.4 defines the library's zero-crossing events; a state machine accepts it as it accepts a guarded `StateSpaceIntegration::ZeroCrossing`. Before, such dynamics were refused for binding no guard.
