- The .NET client connects to a running `sysml-grpc` over gRPC: `Connection.OpenAsync` reaches the service `ConnectionOptions.Address` or `$OPENSYSML_SERVICE` names, asks it `GetServerInfo` once and keeps the answer as `ServerInfo` and `Capabilities`, with a constant for every capability the service declares, and checks an exact `Version`, or else the release `$OPENSYSML_GRPC_VERSION` names (as the other clients do), and `RequireCapabilities` against it. `Connection.CallAsync` calls any method with the generated messages, refusing a method or message pairing the schema does not have before sending anything. Failures are typed: `ServiceException` for a status the service sent, `TransportException` for an unreachable, non-HTTP/2, malformed, oversized or late answer, both `CallException`s with the call's `StatusCode` and `Method`, `CapabilityException` (also for a call the service refuses for a capability it does not have), `StaleServiceException`, `ArgumentException` for an option refused before anything is sent, and the standard cancellation and disposal exceptions.
- The .NET client carries a bearer token for a service that requires one: `ConnectionOptions.Token`, else `$OPENSYSML_GRPC_TOKEN` (`ConnectionOptions.TokenVariable`), is sent on every call as `authorization: Bearer` over every protocol. A token must be the `b64token` the service accepts, an `authorization` header in `Headers` takes the place of the variable and is refused beside `Token`, the token is never logged, and credentials sent over cleartext HTTP to another machine are logged as a warning. A loopback address, where every private service listens, is reached directly, never through the default proxy (`HTTP_PROXY` or the system's settings), which would otherwise read the token and the request in cleartext. A service's `Unauthenticated` is an `AuthenticationException`, a `ServiceException` saying whether credentials were sent and how to supply the right ones; a proxy's HTTP 401 page stays a `TransportException`.
