- `sysml -project-init [-publisher P -name N]`, `-add <iri>[@<constraint>]`, `-install`/`-sync` and `-lock` give `sysml` the write side of KerML 1.0 §10.3 project interchange: a project declares a usage of any repository carrying `.project.json` at a release tag — `pkg:github/<org>/<repo>[#<subpath>]`, `pkg:gitlab/…`, a git URL, a `.kpar` URL or a local path read in place — and the release is fetched (the host's tag archive over HTTPS, a shallow `git clone` of the tag otherwise), its `.project.json` checked against the tag, its `.meta.json` checksums verified, and installed under `lib/<publisher>-<name>_<version>/` with the projects it uses in turn, pinned in a deterministic `.project.lock.json` (resource, version, source, tag, commit, SHA-256 digest, closure). Version constraints now take `^`, `~`, `>=`/`>`/`<=`/`<` ranges and intersections besides an exact version. The loader reads `lib` as a well-known library directory beside `.sysand/lib`, matches a usage through the project's lock first and by publisher and name slugs otherwise, and stays offline; a `sysand-lock.toml` is read as a version hint and never written.
