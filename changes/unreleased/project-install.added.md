- `sysml -project-init [-publisher P -name N]`, `-add <iri>[@<constraint>]`, `-install`/`-sync` and `-lock` give `sysml` the write side of KerML 1.0 §10.3 project interchange: a project declares a usage of any git repository carrying `.project.json` at a release tag — `pkg:git/<host>/<path>[@<constraint>][#<subpath>]`, a clone URL normalized to that form, a `.kpar` URL or a local path read in place — and the release is resolved with git on any host (`git ls-remote --tags`, a shallow clone of the tag, the commit recorded; the host's tag archive over HTTPS as a fast path where one is served), its `.project.json` checked against the tag, its `.meta.json` checksums verified, and installed under `lib/<publisher>-<name>_<version>/` with the projects it uses in turn, pinned in a deterministic `.project.lock.json` (canonical resource, version, remote URL, tag, commit, SHA-256 digest, closure). Version constraints now take `^`, `~`, `>=`/`>`/`<=`/`<` ranges and intersections besides an exact version. The loader reads `lib` as a well-known library directory beside `.sysand/lib`, matches a usage through the project's lock first and by publisher and name slugs otherwise, and stays offline; a `sysand-lock.toml` is read as a version hint and never written.
