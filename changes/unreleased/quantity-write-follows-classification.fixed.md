- A quantity written or bound to a feature is now held exactly where `istype` affirms the feature's type of it (KerML 8.3.3.3.4): a quantity is a `ScalarQuantityValue`, so a feature typed by `Real`, `Number`, a subtype of either or an unrelated definition refuses it with the write's type mismatch, where the run time used to hold `10.0 [m] / 2.0 [s]` in a `Real` attribute; `NumericalValue`, `TensorQuantityValue` and a quantity kind of the unit's dimension hold it as before. Declare such a feature by the quantity value type it measures (`ISQ::SpeedValue`). A quantity a feature of a quantity value type holds is of that type from then on, so a sibling type refuses it (SysML v2 9.8.9.1: an energy held by an `EnergyValue` feature is not written to a `TorqueValue` one, though both are measured in `J`), while one `[` constructs or an operator computes is held by either. A feature typed by a measurement reference (a unit, scale or coordinate frame) still holds a quantity written to it unjudged (`hp : PowerUnit = 745.7 [W]`), as before.
