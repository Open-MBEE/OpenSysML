- Document prose can be written as Markdown: a `rep language "markdown" /* ... */` directly inside a `Document` or `Section` expands in declaration order into paragraphs and lists, and one inside a `part : Paragraph` is that paragraph's content, the part keeping its name as `Ref` target and anchor. Emphasis, strong, code spans, links, autolinks, `[label](sysml:<target>)` references with the `Ref::target` resolution rules, and `$...$` inline mathematics map onto the existing runs, so the Markdown, HTML and PDF backends are unchanged; every run keeps its position inside the body. A textual representation in a language no document parser serves, a Markdown construct no content block renders (named with its body line), a body on a block other than a document, section or paragraph, and a paragraph body that is not exactly one paragraph are typed planning errors (`unsupported-markup-language`, `unsupported-markup-construct`, `misplaced-markup-body`, `markup-body-not-paragraph`) instead of a silently dropped `rep`.
- `:>> text = "..."` is the spelling the manual and examples now use for a paragraph's text; `attribute redefines text = "..."` stays equivalent.
