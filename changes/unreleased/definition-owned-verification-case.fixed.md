- A verification case declared inside a `part def` now runs as a feature of an object of that definition, so its body reads the owner's features: `-validate=<object>`, `-requirement`, `-satisfy` and the gRPC `validate_instance`/`verify_requirement`/`verify_satisfaction` report its verdict once per object of the definition the check is about, naming the object, and `-analysis "<Def>::<case> <object>"` (and `run_analysis` with a subject) runs it on the object given as the case's owner rather than refusing it for declaring no subject; with no object it runs on the single object of the definition the run holds and refuses to choose between several. A `satisfy` without `by` that a definition states is likewise checked on the object of that definition.
