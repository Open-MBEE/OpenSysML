- The Go client can set every option of a conversion: `WithDocuments(names...)` writes only the named documents of a parsed model, `WithCompact()` writes the compact `api-json-compact/1` document, `WithOmitDerived(keep...)` trims its derived properties to the ones kept, and `WithCheckDiagnostics()` adds the semantic check's diagnostics, each with its severity and code, to `Conversion.Diagnostics`. Each is refused as `CodeUnimplemented` before the call when the service lacks `convert_documents`, `convert_compact` or `convert_check_diagnostics`. The package re-exported those capabilities but had no way to ask for them.
- The Go client checks the capability the service names for a call before sending it, as its option checks already did: `Convert*` (`convert`), `Migrate*` (`migrate`), `ApplyEdits` (`apply_edits`), `ParseDocuments` (`parse_sources`), the `Verify*` calls, `ValidateInstance` and `EvaluateCalc` (`verification`), `Query` (`query`, and `query_order_by` with `OrderBy`), `QueryOSLC` (`oslc_query`), `ElementProperties*` (`element_properties`), `RunDocumentQuery` (`document_query`), `RenderDocument` (`render_document`), `WithStrictConformance` (`strict_conformance`), `WithLanguage` on inline content (`inline_language`) and `WithSubject` (`evaluate_subject`). The package now declares `CapabilityQueryOrderBy` and `CapabilityVerdictNotes`, and the client parity page marks a Go capability bound only where the package gates or decodes by it: `render_document_file_name` is not.
