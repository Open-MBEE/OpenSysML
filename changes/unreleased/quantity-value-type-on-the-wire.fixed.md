- A quantity read from the service now carries the quantity value type it is held as (`Quantity.value_type` in the protobuf schema, `valueType` in JSON, and a field of that name on every client's quantity), and a client sends it back with the quantity, so a quantity read off an `EnergyValue` feature and passed to a calculation taking a `TorqueValue` is refused over the wire as it is in the model, where the type used to be dropped on the way out and the sibling type accepted it. A quantity a client builds, or one an operator computes, carries none and is judged by its dimension as before. The service refuses a value type that names no quantity value type of the model or one of another dimension than the unit.
