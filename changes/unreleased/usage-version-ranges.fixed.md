- A usage's `versionConstraint` is read as an npm-style semver range — exact, `=`/`v` prefix, `<` `<=` `>` `>=`, `^`, `~`, `x`/`*` wildcards, hyphen ranges, space/comma as AND, `||` as OR, pre-releases ordered as semver 2.0.0 and admitted only where the range names their release — and the highest installed version in the range is taken, on the publisher/name match and by elimination alike; before, only an exact version was understood, so a range never linked by elimination and on the name match the latest installed version was taken regardless. A constraint no installed version satisfies, or one the grammar does not read, is now a `project.load` warning at the consumer's `.project.json` and the usage selects nothing, where before the latest version was taken silently.
