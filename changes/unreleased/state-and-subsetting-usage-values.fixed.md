- A state usage's own `in` values now reach its performance as an action usage's do: `ExecuteState` on `state m : M { in n = 3; }`, `exhibit m`, and `exhibit state es : M :> m` read `3` where the definition's guard names `n`, the usage's parameter redefining the definition's by position rather than hiding it, while an unvalued usage parameter keeps the inherited default. A performed action subsetting a valued usage — `perform action pt : Step :> t` in an action body or on a part definition, and `perform t` on a part — performs through that usage, so its parameters hold the usage's values; explicit inputs and arguments still win.
