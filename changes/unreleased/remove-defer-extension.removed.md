- **The `defer <event> [, <event>]*;` state member, an OpenSysML extension SysML v2 has no counterpart for, is removed from the language, the runtime and every surface.** `defer` is an ordinary name (`state defer;`, `attribute defer : Real;`, `defer.x`), and a legacy `defer` member in a state body is one `defer-notation-removed` parse error in either conformance mode, pointing at the standard encoding of a deferred signal: an ordered buffer (`item deferred : Sig[*] ordered;`), a do action whose accept loop keeps each occurrence while the state is active, and an exit action that sends each kept occurrence to `self` — what the SysML v1 migrator writes (`docs/reference/sysml-v1-migration.md`, *Deferred signals*), which executes unchanged. Gone with the notation: the runtime's deferral queue and its priority rule (a deferring substate no longer outranks a transition of an enclosing state or a sibling region — a transition that is enabled fires), the `Sig / defer` view labels, the `sysx:DeferMember`/`sysx:deferredEvent` RDF terms (a Turtle file carrying them is refused with a diagnostic rather than read with the member dropped), the REPL's "deferred by the active state" report, and the `defer` grammar and completion entries. Three things the extension expressed have no standard spelling and are documented as losses in `docs/project/spec-compliance.md`: the deferring state's priority, one pooled replay order across different signals, and a deferred operation call.
