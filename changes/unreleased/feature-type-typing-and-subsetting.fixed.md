- `GetElementProperties` (`element_properties` in the clients) and the `api-json` element form now answer `Feature::type` with a feature's own typings **and** the types it inherits from the features it subsets or redefines, as the Symbol API already did (KerML 1.1 §8.3.3.3.4 `deriveFeatureType`; #2198). `part pBoth : V :> q;` beside `part q : T;` answered `type` = `[V]` and now answers `[V, T]`; an inherited type a written one already specializes is still left out. The `api-json` element form keeps the written typings as the `type` entry of `sysx:mappingValues`, so the document still reads back to the same graph and the same notation, and the properties derived from `type` (`definition`, `partDefinition`, …) follow it.
