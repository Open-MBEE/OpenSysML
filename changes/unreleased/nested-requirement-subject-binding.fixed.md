- A requirement usage a definition owns now holds an object of the usage itself when its body only restates the subject, so a subject bound from the owning object's features — `subject s :>> s = sub;`, `subject s = sub;`, a bare `subject = sub;`, a sibling part, or a satisfy usage's `by pa` — or a `default` applying when nothing else values it (`subject s :>> s default sub;`, the library objective's `default Case::result`) — reads that value through the owning object (`p1.rq.s`, `ca2.obj.subj`), and `p1.rq.result` is the requirement's verdict on it, as `-validate` on the object already computed; a subject nothing binds stays `<undetermined>`. `satisfy requirement r : R by x;` is checked against the conditions `R` states instead of being refused as satisfying no requirement, and a negated one reads `R`'s verdict as its `result` while its standing is the negation.
