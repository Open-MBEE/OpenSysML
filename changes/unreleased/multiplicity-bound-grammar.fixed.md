- **A multiplicity bound is a literal or a feature name, as the grammar has it.** A bound written as an arithmetic or other operator expression (`[n+1]`, `[1..2*3]`), a cast (`[0..(2 as Integer)]`), a parenthesised expression (`[(n)]`), a feature chain (`[a.b]`), an invocation (`[f()]`) or `null` is now a syntax error, `a multiplicity bound must be a literal or a feature name (KerML.xtext MultiplicityExpressionMember)`, as it is for the pinned pilot; a computed bound is written as a feature value and named (`feature n : Natural = 2 + 1; feature d [n];`). The `validateMultiplicityRangeResultTypes` documentation now cites KerML 1.1 8.3.4.11.2 `MultiplicityRange`.
