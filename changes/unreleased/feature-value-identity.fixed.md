- An object's feature values are keyed by the feature, not by its name: for `part def Both :> A2, A1 { attribute b :>> A1::a = 3.0; }` the name `a` on an object of `Both` is the surviving `A2::a` and reads its own value (`2.0`), in either order of the generals and whether a definition or a usage owns the redefinition, while `b`, and `a` read as an `A1` (`(bd as A1).a`, a `ref : A1`), read `3.0`. Before, the redefiner's value was aliased to every namesake, so `bd.a` read `3.0` and the shape could hold the removed `A1::a` under `a`. A feature inherited along two paths is one feature and keeps reading the redefiner's value under every name.
