- `this` written in a behavior body now denotes the context occurrence the member read `.this` answers: the object owning the performance for an action, state, calc or constraint a part owns (`Objects.kerml` `ownedPerformances::this default that`, `Parts.sysml` "the `this` reference of an ownedAction is always its owning Part"), the owner's `this` for a subaction (`Performances.kerml` `subperformances::this default (that as Performance).this`), and the performance itself only when no object owns it. A typed action usage a part owns no longer answers its own occurrence for `this`, `self.this` or `this.<feature>` in its definition's body, and `this.<feature>` written in a behavior definition resolves against the owning object's features rather than the definition's own; a package-level action nothing performs still reads `this` as undetermined.
