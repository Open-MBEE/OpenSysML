- A qualified name looked up through the service now resolves from the root namespace the way a reference written in the notation does (KerML 8.2.3.5), through the visible memberships of each namespace. `GetElementProperties` and the clients' symbol lookups by qualified name (`Model.get` in Python, `LookupSymbol` in Go, `symbolById` in TypeScript, `symbol`/`findSymbol` in Java, `symbol` in Rust, `get` in Julia and MATLAB) find a name that a `public import` re-exports — a membership import (`Facade::Pump` for `public import Lib::Pump;`), `Lib::*`, and the recursive `Lib::**` for the members of nested namespaces — and answer with the imported element; a symbol lookup of an alias answers with the element it is for rather than the alias; and a `private` or `protected` member, which used to be found from outside its namespace, is not. The new `GetSymbolRequest.resolve_name` asks for this reading, and the clients set it; without it the id is one the service reported (a child, a member, a specialization target), which still fetches that element whatever its visibility. The Python client no longer discards the answer when the resolved symbol carries another id, which is why it missed a wildcard re-export the Go client found. In the resolver, a qualified reference no longer crosses a `private` membership or recursive import, or a `protected` import, from outside the importing namespace (`Hidden::Pump` for `package Hidden { private import Lib::Pump; }` is now unresolved, as the wildcard form already was).
