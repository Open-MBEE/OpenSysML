- **A strict SysML v1 migration writes deferred signals in standard SysML v2.** Under `-strict` a state's `deferrableTrigger` is no longer dropped: the state gets an `item` buffer, a do action whose accept loop keeps each occurrence while the state (substates included) is active, and an exit action that sends the kept occurrences back to the object once the state is left — every member named through `MigrationMetadata::SynthesizedName`, merged beside the state's own do and exit behavior, one loop per signal and per route the signal reaches the object by (from the object itself and `via` each port it arrives at). A signal a transition out of the state accepts without a guard is not kept, as in v1; one a guarded transition accepts is kept while the guard is false. In both modes the state is annotated `@MigrationMetadata::DeferredEvent { ref :>> signal : Sig; }`, a new definition of the bundled `MigrationMetadata` library. An explicit `send … to self` now reaches the sending object like a send with no target, and a state's `item` usages are state data like its attributes.
