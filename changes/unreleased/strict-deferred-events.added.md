- **A strict SysML v1 migration writes deferred signals in standard SysML v2.** Under `-strict` a state's `deferrableTrigger` is no longer dropped: the state gets an `item` buffer, a do action whose accept loop keeps each occurrence while the state (substates included) is active, and an exit action that sends the kept occurrences back to the object once the state is left — every member named through `MigrationMetadata::SynthesizedName`, merged beside the state's own do and exit behavior, one loop per signal and per route the signal reaches the object by (from the object itself and `via` each port it arrives at). A signal a transition out of the state itself accepts without a guard is not kept, as in v1; one a guarded transition, or a transition out of a substate, accepts is kept while the guard is false or the substate inactive; a state whose completion transitions are all guarded keeps the signal too, and then leaves by triggered transitions alone; only a transition the strict output writes counts for either rule, so one into a pseudostate with no v2 form, a final state of another region or a state of another machine takes no signal from the deferral. A signal the state also defers a general of, or defers twice, is kept by the general's or the first trigger's loop alone, not twice. An internal transition, written as a self transition, flushes the buffer to self on its re-entry and the restarted accept loop keeps the occurrences again. In both modes the state is annotated `@MigrationMetadata::DeferredEvent { ref :>> signal : Sig; }` for every signal it declares deferrable, kept or not — a new definition of the bundled `MigrationMetadata` library. An explicit `send … to self` now reaches the sending object like a send with no target, a state's `item` usages are state data like its attributes, and a transition that fires on a message takes it alone: the accept of a do behavior of the state it fires out of, or of a state enclosing that, no longer takes the same occurrence too.
