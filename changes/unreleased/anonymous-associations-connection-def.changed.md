- **Every v1 association is a `connection def`.** An anonymous association was written only as its member-end properties; it is now a `connection def` named after its end types (`WheelToCar`, marked `MigrationMetadata::SynthesizedName`) whose one usage is a `connection` typed by it joining `part` usages of the two end types, as a named association already was. An end a class owns crosses the property it is written as (`end wheels : Wheel crosses car.wheels;`), the mapping's feature chain, where that is sound; where it is not (an untyped opposite end, an end type not written or written as a usage, a non-binary association) the def is still written, the end crosses nothing and the report says why. An end the association owns carries its multiplicity as the cross multiplicity (`end [0..*] ref car : Car;`), so the "End feature must have multiplicity 1" warning no longer fires on migrated ends. A link of an anonymous association now specializes its def like a link of a named one.
- **A tree view draws a `connection def` as a line between its end types.** A `connection def` whose two ends are typed by drawn definitions, and that carries no other member, is drawn as a line between their boxes labelled with its ends (and its name, unless a migration made it up), as a block definition diagram draws an association, instead of as a box of its own; an association block stays a box.
