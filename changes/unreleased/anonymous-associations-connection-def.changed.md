- **Every v1 association is a `connection def`.** An anonymous association was written only as its member-end properties; it is now a `connection def` named after its end types (`WheelToCar`, marked `MigrationMetadata::SynthesizedName`) whose one usage is a `connection` typed by it joining `part` usages of the two end types, as a named association already was. An end a class owns crosses the property it is written as (`end wheels : Wheel crosses car.wheels;`), the mapping's feature chain, where that is sound; where it is not (an untyped opposite end, an end type not written or written as a usage, a non-binary association) the def is still written, the end crosses nothing and the report says why. A `private` or `protected` property an end crosses is written visible, as one a connector reaches is, and the report says which def reaches it. An end the association owns carries its multiplicity as the cross multiplicity (`end [0..*] ref car : Car;`), so the "End feature must have multiplicity 1" warning no longer fires on migrated ends. A link of an anonymous association now specializes its def like a link of a named one.
- **A tree view draws a `connection def` as a line between its end types.** A `connection def` whose two ends are typed by drawn definitions, and that carries no other member, is drawn as a line between their boxes labelled with its ends (and its name, unless a migration made it up), as a block definition diagram draws an association, instead of as a box of its own; the line wears the def's `Style` and `Route` and carries its `Note`s. An end that crosses a `part` or `ref` the tree draws as an edge from its owner takes that edge over, so a composite association is one line with the composition's diamond and the part's name, wearing the def's `Style` and `Route`, not a composition and a line; the line is plain, not the heavy connector of an interconnection diagram. An association block, a def that inherits its ends or specializes another, or one whose end holds a qualifier stays a box. The migrator pins a v1 association's diagram route to a def the tree draws as a line (`Route about WheelToCar`) instead of reporting it `not drawn` (the route of one kept as a box still is), and a shown end the association owns exposes the def, not the end, so same-named ends of two defs on one diagram raise no duplicate-member warning.
