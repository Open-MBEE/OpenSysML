- The solver compares a value-typed variation point — one whose every variant declares a value, `variant attribute low : Integer = 3;` — by the value its selection stands for, as KerML `BaseFunctions::'=='` is value equality for data values and the evaluator already answers: `P == P::V`, `P == 3`, `P != P::V` and the quantifier forms `P->forAll { in ref w; w == P::V }` hold for every variant declaring that value, so `%configure`, `%solve`, `%check` and the MCP `configure` tool now permit the same selections `%validate` accepts instead of selecting one variant by name. Two variants named outright still compare as the choice itself, an object-valued variation still compares its selection, and a point whose variants declare values and objects both is refused with that reason.
