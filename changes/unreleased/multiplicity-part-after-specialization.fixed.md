- **A MultiplicityPart may follow the specializations a usage states where its name would go.** `:>> values ordered : Real;`, `:>> values ordered nonunique;` and `:>> values [5] ordered = (…);` now parse as the grammar reads them (`FeatureSpecializationPart: FeatureSpecialization+ MultiplicityPart? FeatureSpecialization*`), in SysML and KerML files alike, with `ordered`/`nonunique` recorded on the feature; `ordered` was read as the usage's name and rejected as a reserved keyword.
