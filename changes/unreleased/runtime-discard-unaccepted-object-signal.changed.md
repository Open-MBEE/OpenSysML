- **A signal nothing of its object takes is discarded, not held for a later state.** A message a model sent to an object whose state machines were settled in a configuration with no transition enabled for it stayed on the bus until a state entered later accepted it, so a stale `Abort` sent during one alignment aborted the next one as soon as it began. Once the object's machines are settled and none of its do behaviors or performed actions is parked at an accept for it, the first of its machines takes the message off the bus and drops it, reported as a dropped dispatch, as UML discards an occurrence that triggers no transition and is not deferred. A message routed to a port, or to a named receiver other than the object, stays in flight as before.
- **A deferring state's own accept of the deferred signal takes it before the keeping loop does.** The standard deferred-signal encoding kept every occurrence of the deferred signal while the state was active, even one the state's own do behavior was parked at an accept for, so the behavior never went on and the occurrence was replayed on exit. The keeping accept now yields to a branch of the state's do behavior parked for the same occurrence, which consumes it; an occurrence nothing of the state consumes is kept, as before.
