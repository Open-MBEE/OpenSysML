- The SysML v1 migrator writes a UML Interaction as a SysML v2 sequence — an `occurrence def` (a `verification def` for a test case) whose lifelines are usages typed by the represented property's type, holding `event occurrence`s ordered by `then`, each message a `message` between the events it leaves and reaches (a signal as the payload, a call performed at the receiving event, a reply carrying the call's result), interaction uses as ordered occurrence usages with their arguments bound, state invariants as asserting events — instead of an executable `action def` scenario of sends and accepts; lifelines standing for the Interaction's own properties (a use case's black-box scenario) now resolve, and a SysML Sequence Diagram becomes a `SequenceView` view carrying the tool's lifeline `Layout`s and message `Route`s, which the sequence renderer and the layout lint now read. Combined fragments, duration and time constraints, execution specifications and gates are reported where v2 sequence notation has no form; reply assignments and arguments reading the owning block's features are reported as not written.
