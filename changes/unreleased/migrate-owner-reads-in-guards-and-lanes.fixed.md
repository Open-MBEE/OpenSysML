- **The SysML v1 migration counts every read of a block's features its writer spells when deciding how a block's behavior reaches them.** The analysis that gives a nested `action def` its `in ref context : <Block>;` parameter, or writes the behavior as an action usage of the block, now resolves opaque bodies as the writer does — guards on control flows, pin values and other opaque expressions as much as opaque actions, and names a swimlane resolves through one of the block's parts (`'ESW Seq'.i`) as much as the block's own features. Before, a definition whose only owner reads were guards, or whose reads went through a partition's part, read them bare (`if i >= maxSearchCircles`, `assign 'ESW Seq'.i := …`), which the accessibility rules reject; such a behavior is now `context.i` in a def, or bare in a usage whose body runs on the object. A definition nested in a behavior written as a usage takes the block as its context, since it is its own occurrence; a definition whose calls bind through ports keeps the port owner's context. A behavior that reads its owner and is called only from other definitions of the block keeps the parameter when they bind it, without making a caller outside the block name an object of it. A name a body declares as a local (`let count = 1; count += 1;`) is no read of the block's feature so called, and the parameter a definition takes is the same whichever of the blocks calling each other's behaviors the migration reaches first.
