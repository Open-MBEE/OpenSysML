- **The SysML v1 migration counts every read of a block's features its writer spells when deciding how a block's behavior reaches them.** The analysis that gives a nested `action def` its `in ref context : <Block>;` parameter, or writes the behavior as an action usage of the block, now resolves opaque bodies as the writer does — guards on control flows, pin values and other opaque expressions as much as opaque actions, and names a swimlane resolves through one of the block's parts (`'ESW Seq'.i`) as much as the block's own features. Before, a definition whose only owner reads were guards, or whose reads went through a partition's part, read them bare (`if i >= maxSearchCircles`, `assign 'ESW Seq'.i := …`), which the accessibility rules reject; such a behavior is now `context.i` in a def, or bare in a usage whose body runs on the object. A definition nested in a behavior written as a usage takes the block as its context, since it is its own occurrence; a definition whose calls bind through ports keeps the port owner's context. A behavior that reads its owner and is called only from other definitions of the block keeps the parameter when they bind it, without making a caller outside the block name an object of it. A name a body declares as a local (`let count = 1; count += 1;`) is no read of the block's feature so called, and the parameter a definition takes is the same whichever of the blocks calling each other's behaviors the migration reaches first. Definitions of the block calling each other in a cycle all take the block once one of them reads it, binding each other's parameters to their own rather than to the caller's occurrence; a definition no block owns takes the block its callees read as its own parameter; a part holding a collection of a block's objects, or a number of them its bounds do not tell, is no one object for a caller to bind a parameter to or perform a usage on, so the caller leaves it unbound and says so; and a swimlane over one of the block's parts is a read of the block, not a port of it, so a definition reading its owner through one keeps the owner as its context over another block's ports, whose send then loses the port and says so. A body the writer keeps as a comment — a guard or an opaque action it cannot translate — reads nothing of the block, so it neither makes the behavior a usage of the block nor displaces the port owner's context, and a definition declares its context parameter only for names it writes; a behavior whose only such reads are in kept-as-comment bodies is now a plain definition.
