- **Source-preserving authoring now writes comments and line notes, and documentation text is no longer over-restricted.** The new `add_comment` operation writes `comment [name] [about a, b] [locale "..."] /* ... */` in an owner's body or at the top level, and `add_note` writes a `// ...` line note above a named declaration that later edits keep in place. Both require the new `comment_authoring` capability, and the Go, Java and Python clients expose them (`Editor.add_comment`, `Editor.add_note`). `Comment::body` now follows the KerML body-processing rules exactly in the parser, the RDF and API JSON exports and their import, so documentation and comment bodies with empty text or white space at either end are written and read back unchanged; only `*/` and carriage returns are refused.
