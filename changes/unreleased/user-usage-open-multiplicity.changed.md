- A usage the model itself declares with an open multiplicity now reads closed over the model, by the rule the library collections already follow (KerML 1.0 §7.3.2.2, §7.4.11, §7.4.12): a lower bound of 0 that nothing declared meets is met by no value, so `part wheels : Wheel[0..*];`, `item cargo : Box[0..4];`, `ref part spares : Wheel[*];`, `part spare : Wheel[0..1];`, `attribute tags : String[0..*];` and `part nested : Wheel[0..*] { part hub; }` read as the empty sequence on a package-level usage (`car.wheels`), bare or qualified (`Probe::wheels`), and in a constraint or calc (`size(wheels) == 0` is `true`), exactly as on `new Car()`, instead of `<undetermined>`. A lower bound of 1 or more that nothing declared meets (`part w : Wheel[1..*];`, `part r : Wheel[2..4];`) stays `<undetermined>` of its bounds, carrying what subsetting usages contribute; a subsetting usage meeting the bound (`part fl : Wheel :> fitted;` under `fitted[1..*]`) or a feature value (`= (w1, w2)`) closes the count. An unbound input (`attribute n : Integer;`) stays `<undetermined>`, as does a parameter of a behavior usage nothing has invoked (`in i : Integer[0..1]` of `action act : Act;`), whatever its multiplicity: its invocation supplies it (SysML v2 §7.17.2, KerML 1.0 §7.4.7). The same rule now applies to a package-level usage subsetting an open one (`part x : Wheel[0..*]; part y : Wheel :> x;` makes `x` the collection holding `y`) to a library collection of a nested usage (`car.act.subactions` is the nested action its definition declares, as on `new Car()`), and to the library's optional `shape [0..1]`, which reads as the empty sequence rather than `null`, as it does on an instantiated object. A directed feature of a port or part definition (`in attribute v : Integer[0..1]` of a port) is no behavior parameter and reads closed like any usage, and subsetting contributes transitively at package level (`leaf :> l2 :> l1` makes `l1` hold `leaf`).
