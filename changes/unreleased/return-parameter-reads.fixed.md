- A result parameter an object inherits from the library behavior it enacts now answers the object's own evaluation instead of failing as a missing feature: `RequirementCheck::result` on a requirement, viewpoint or concern object is its required conditions conjoined, `Case::result` is the case's own `return` parameter, and `VerificationCase::verdict` is the verdict the case's body produced; an evaluation reading an unbound input (a subject nothing supplies) is undetermined. A verification usage read as a calc answers the same inherited `verdict`/`result` names.
