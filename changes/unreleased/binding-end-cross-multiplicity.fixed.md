- A binding connector's end multiplicities are now read as the cross multiplicities they are (KerML 1.1 §7.4.5.2, §8.4.4.5.1, §8.4.4.6.1): how many of that end's values each value of the other end is linked to, a binding linking a value to itself alone. `bind [1] xs = [1] ys` makes the ends hold the same values however many there are, instead of being refused with "links [1] of xs, which holds 2 value(s)"; `bind [1] few = [0..1] many` is violated when `many` holds a value `few` lacks, where it used to hold; ends that are all optional with no links declared on the connector (`bind [0..*] a = [0..*] b`) no longer determine either end; an end requiring two or more values per value of the other is a multiplicity violation; and a binding that requires a link over an end reaching no object is a violated verdict rather than no verdict or a multiplicity error.
