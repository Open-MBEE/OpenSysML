- **`ExecuteState` on a performer reports the performer's attributes in `final_context`.** A machine run with `performer_symbol_id` (`execute_state(..., performer=...)` in the Python client) already took its guards against the performer's feature values and wrote the performer, but the executed response carried only the machine's own data, so two performers leaving different values looked alike unless their runs rested in different states. `final_context` now holds the performer's attributes under `this.` (`this.speed`, `this.seen`), as an explored outcome's `outputs` already did.
