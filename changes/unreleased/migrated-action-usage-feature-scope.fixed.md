- **An action usage a part definition owns writes the part's features when performed on a part declared in another file.** `%action Plant::fill plant` over a migrated `Plant` and a `part plant : Plant;` loaded from a second file failed with `name is not in scope of the behavior body: runs is a feature of plant, which the body does not name`, though the body names `runs` through its owning definition. The runtime took the owning definition and the performer's type for different declarations when each file resolved to a symbol of its own for `Plant`; it now compares them as one element, so the performance writes `plant.runs` and `plant.tank.volume` as it does when both are declared in one file. A body an object performs without owning it is still refused the object's features.
