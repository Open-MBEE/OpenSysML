- Every SysML usage and KerML feature now directly specializes the base library usage its kind implies (`Parts::parts`, `Items::items`, `Ports::ports`, …, `Links::links`, `Base::things` for a usage of no kind), as the `check*UsageSpecialization` clauses and KerML `checkConnectorSpecialization` state: `istype`, `Conforms` and `DirectSupertypes` report the base usage as a general, while the usage's types stay those of the kind's base definition, so `that`, parameter and role redefinitions, multiplicities and runtime classification are unchanged. A feature typed by a metaclass subsets `Objects::objects` rather than `Metaobjects::metaobjects`, a feature typed by a datatype subsets `Base::dataValues`, a KerML `datatype` or `function` declaration subsets no base feature, and an individual occurrence usage subsets `Occurrences::occurrences` beside being typed by `Occurrences::Life`, which is now its feature type rather than `Occurrences::Occurrence`. A library record names the base usages a symbol's kind implied among its supertypes, so a model loaded from records tells them from the declared ones.
