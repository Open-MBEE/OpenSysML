- A feature read at namespace level (`sysml -e P::xs`, a bare expression or `%eval` in the REPL, gRPC `Evaluate`) now holds its value in the feature's effective multiplicity, as the same feature read on an object already did: a `[0..*]` attribute valued `= 4` reads `[4]` on both, where the model-level read printed the bare `4`. An at-most-one feature (`[1]`, `[0..1]`, a bare `attribute x : Integer`) still reads its one value bare, and arithmetic and comparison over the read (`P::xs + 1`, `P::xs == 4`) are unchanged. A parameter stating no multiplicity is held to `[0..*]`, so its one default reads as a one-element sequence too, and a call of a calc-typed parameter applies the one function it holds.
