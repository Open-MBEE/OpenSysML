- **`===` over sequences is element-wise identity.** `(1, 2.5) === (1.0, 2.5)` is now `false`, as `SequenceFunctions::same((1, 2.5), (1.0, 2.5))` already was: each element must be `===` its counterpart, so an Integer element is never the same as an equal Real one, at any position or depth. `(1, 2.5) === (1, 2.5)` stays `true` and `==` still compares elements by equality. A program compiled with `sysml -compile`, C or Go, gives the same answers.
