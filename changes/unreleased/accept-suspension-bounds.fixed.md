- **Let an accept suspend the whole call chain and work in loop and branch bodies.** An action performed synchronously that reaches an `accept` now parks its caller and every performance above it until a matching message arrives from a sibling branch, another object, `%send` or the clock, where it used to report `ErrAcceptDeadlock` as soon as the call began; an `accept` in a loop body, an `if`/`else` branch or a nested action declared there is now executed in declaration order instead of being refused. `ErrAcceptDeadlock` is reported only when nothing in the run can still post the awaited message, and names the innermost accept and the chain holding it.
