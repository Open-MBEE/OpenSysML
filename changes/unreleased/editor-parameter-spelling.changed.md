- **`add_parameter` writes implicit directed usages by default; explicit `ref` keeps the keyword.** `add_parameter("C", "in", "x", type="T")` now writes `in x : T;` — an `add_member` edit with an empty `kind` writes a directed usage with no kind keyword. Passing `kind="ref"` still writes `in ref x : T;`, which this runtime reads as a performer-bound reference parameter. The new spelling requires the new `implicit_parameters` capability; undirected and abstract spellings are unchanged.
