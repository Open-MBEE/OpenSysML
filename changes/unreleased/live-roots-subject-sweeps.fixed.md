- A declaration instantiated twice (`%instantiate test::b` twice, gRPC `Instantiate` twice) leaves two live objects of its definition, and subjectless verification and checks now see both instead of the newest alone. `%requirement`, `-requirement`, gRPC `VerifyRequirement` and `RunAnalysis` with no subject run a verification case the definition owns once per live object — two bolts give two verdicts, two cars of four wheels eight — as `%satisfy` and `VerifySatisfaction` already did, the REPL labelling the displaced object's verdict `on #1 (displaced from test::b)`. A check of a constraint or requirement the definition owns naming no object is an ambiguous subject naming both (`Bolt #1 (displaced from b), Bolt #2 (b)`) with the hint to check it on one of them, instead of silently answering about the newest; `#1` or `test::b` after the check picks one. A feature of a definition relates every object in its domain to values (KerML §7.3.4.1) and a verification verdict is about the subject of one performance (SysML §7.24.1); the name denoting the newest object is a REPL and service naming policy, which stays. The objects one usage denotes together (`part wheels : Wheel[2];`, `part cheap : Definition [2]`) are still one check subject.
