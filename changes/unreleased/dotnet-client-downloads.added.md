- The .NET client downloads the `sysml-grpc` release a private service is started from when no binary is named, into the shared `~/.opensysml/bin` cache under the lock every client takes, as the Python, Java and Rust clients do: the release `ConnectionOptions.DownloadVersion` or `OPENSYSML_GRPC_VERSION` asks for (a tag, or `latest`, which the GitHub releases API resolves once per open), else the release the client was built with, from `ConnectionOptions.GithubRepo`, `OPENSYSML_GITHUB_REPO` or `Open-MBEE/OpenSysML`, for Linux and macOS on x64 and arm64 and Windows on x64. A cache already holding the release asked for, or the binary `ExpectedBinarySha256` requires when no release was explicitly requested, is started with nothing fetched after checking any committed pin for its recorded release; another release is replaced, with a warning, only once the download verifies. A release asked for is that release or a failure; the release the client was built with gives way to a working cache, then to `PATH`, with a warning, when it cannot be had. A release is trusted only by the SHA-256 digest this checkout pins for it: the checksum served beside it, its bytes and `ExpectedBinarySha256` must all agree with the pin, and any disagreement fails with `ChecksumMismatchException` however good the cache. The client does not verify release signatures, so a release it pins nothing for fails with the new `UnpinnedReleaseException` before anything is fetched, unless `OPENSYSML_ALLOW_UNPINNED_DOWNLOAD` grants same-origin trust to its repository, with a warning. Downloads are HTTPS alone, redirects included, abandoned after 15 seconds of silence, bounded at 512 MiB for a binary and 8 MiB for a checksum or API answer after decompression, cancelled by the caller's token, and never retried; nothing they stage is left behind.
