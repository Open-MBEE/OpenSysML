- CI installs cvc5 through one action, `.github/actions/cvc5`, in place of three copies of a step that asked GitHub for the release zip with a single `curl`: one connection GitHub did not accept within 134 seconds failed `Go queue tests (codegen)` in the merge queue and ejected a pull request whose every other check had passed. The action keeps the zip in the Actions cache under the pinned version and sha256, so a run that restores it verifies it and never asks GitHub; a run that does not downloads it through `scripts/fetch-https.sh` (a 30-second connection limit, 300 seconds an attempt, up to eight retries on any error with curl's doubling delay, within 600 seconds). The digest stays strict on both paths: a restored zip that fails it is downloaded again, a downloaded one that fails it is neither installed, kept nor retried. CircleCI installs through the same `scripts/ci-cvc5-install.sh`, so the pin has one source, `scripts/cvc5-pin.sh`; `tests/hygiene/cvc5_install_test.go` plays the dropped connection, the kept zip and the substituted asset, and fails on a CI file that downloads cvc5 itself.
