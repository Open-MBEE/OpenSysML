- The .NET client has the values the service exchanges as immutable types: `Value`, with one sealed nested class per kind the service sends or reads (`IntegerValue`, `BigIntegerValue`, `RationalValue`, `RealValue`, `QuantityValue`, `SetValue`, `ArrayValue`, `MetaobjectValue`, `UndeterminedValue` and the rest) and a `ValueKind` to switch on, an exact `Rational`, `Quantity` with its `UnitTerm`, and the `ValueList<T>` and `ValueDictionary<TValue>` collections. Values compare by content, a set in any order, an enumeration literal by its declaration and a metaobject by its element; numbers are never converted through a `double`, and Reals keep NaN, the infinities and negative zero. An answer is read only in the schema's canonical form, a malformed one failing as a `TransportException` that names where it is and one of a kind the client does not know as an `UnsupportedValueException` rather than a null. A value sent is refused before sending when no service reads it as an argument, and needs the capability for each kind the service gates wherever the service looks for it; a Rational a `double` holds is sent as that double to a service without `rational_values`. No public method takes or returns a value yet.
