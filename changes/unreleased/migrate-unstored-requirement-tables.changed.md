- **A Cameo Requirement Table or Refine Requirement Matrix is reconstructed from its owning scope.** Cameo stores no content for these two diagram kinds — the `DiagramRepresentationObject` has a `binaryObject` with no `streamContentID` and no `usedObjects`, and the scope is serialized nowhere in the model file — so their views came out empty (`the diagram shows nothing; the view exposes nothing`). The SysML v1 migrator now writes the view of a Requirement Table owned by `P` exposing every `requirement` written under `P` (nested and contained), and the view of a Refine Requirement Matrix owned by `P` exposing every «Refine» written under `P`, the `connection 'A refines B'` and the two usages it joins; both are still rendered `Views::asElementTable`. The report row says plainly that the tool stored no rows (cells) and that the view is reconstructed from the owning scope, with the count exposed, and the view is approximated. A diagram of either kind that lists `usedObjects` or has a symbol stream, or that carries a «DiagramTable»/«DependencyMatrix» application with the tool's scope, is migrated as before.
- **A view rendered `asElementTable` lists each exposed element once.** The table rendering wrote one row per exposed element and one per element declared in it, so an element the view exposes in its own right beside its owner (`expose P::**`, a requirement table exposing a requirement and the one nested in it) was listed twice: under its owner and as a row of its own. A member the view exposes is now left out of its owner's rows and keeps only its own.
