- **A SysML v1 Operation migrates to its block's composite `action <op> { … }` usage, and every call chains to it.** The migrator no longer synthesizes an `action def <Op>` plus an `action <op> : <Op>;` feature: the usage itself carries the parameters, the pre/postconditions as `assert constraint` and the method as body, keeping a «DirectedFeature» direction. A CallOperationAction is written `perform action <call> ::> <target>.<op>` for `this`, features of `this` and parts a port connects to; a call on an object handed in or created is an action usage whose `in <pin> : <Block>` parameter a nested perform chains through, its pins bound to the operation's parameters. The OMG mapping's `perform action <op>` on the block is not written because it is one performance the object enacts, which a call would join rather than invoke; the migration reference says so.
