- Implied generalizations are audited row by row against KerML 1.1 Beta 2 §8.4 and SysML v2 1.1 Beta 2 §8.4 and the pilot's `ImplicitGeneralizationMap` (`docs/project/implicit-specialization-audit.md`), and the rows found missing or wrong are fixed: control nodes subset `Actions::Action::forks`/`joins`/`merges`/`decisions`; accept, send and terminate actions subset `acceptActions`/`sendActions`/`terminateActions` and the matching `Action::…Subactions`; a transition subsets `States::StateAction::stateTransitions` in a state and `Actions::Action::decisionTransitions` in an action; substates of a non-`parallel` state subset `exclusiveStates`; actors, stakeholders, framed concerns, a view's viewpoints, event occurrences and an objective's `verify` subset `RequirementCheck::actors`/`Cases::Case::actors`, `stakeholders`, `concerns`, `View::viewpointSatisfactions`, `Occurrence::timeEnclosedOccurrences` and `VerificationCase::obj::requirementVerifications`; `satisfy` and `assert` usages subset the `(not)satisfiedRequirementChecks` and `(asserted|negated)ConstraintChecks`; a flow usage subsets `Flows::messages`, and `flows` only when it declares ends; a KerML flow subsets `Transfers::transfers` (`flowTransfers` with ends, `flowTransfersBefore` for a succession flow), a `metadata` feature `Metaobjects::metaobjects`, a composite or portion feature `suboccurrences`/`subobjects`/`portions`, and an association or connector end `Links::Link::participant`. The extra `Flows::Message`, `Actions::SendAction`, `Actions::AcceptAction` and (for `individual` usages) `Occurrences::Life` definition edges that neither specification names are gone. The graph-backed rules (RDF and API JSON export) reconstruct the same roles and the owner's `parallel`, so an accept, send or terminate action, an event occurrence, an objective's `verify` and the substates of a `parallel` state carry those subsettings there too.
