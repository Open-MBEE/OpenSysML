- Strict conformance (`-validate -strict`, the REPL's `%strict on`, `strict_conformance` on the wire) now rejects a `:>>` redefinition whose name resolves only through an import or the enclosing namespace while the declaring type owns or inherits no such member: `sysml -validate -strict` reports `redefinition-resolves-to-nothing` at the written target, naming the member and the type (for example `member length redefines nothing resolvable in HotLegPipe`), instead of exporting a `redefines` handle with no target. The default mode reports nothing, so existing models are unaffected. Chain redefinitions stay with their own rule, and a name that names no element stays a name-resolution finding.
