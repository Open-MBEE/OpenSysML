- The .NET client runs a document query written in place of a name. `Model.RunInlineDocumentQueryAsync` sends the result expression of a `calc def` specializing `DocumentQueries::Query` — `Project(WhereType(Descendants(Named("Vehicles")), "PartUsage"), ("name", "mass"))` — in `RunDocumentQueryRequest.inline_query`, with the same `DocumentBinding`s and the same typed `DocumentQueryResult` as `RunDocumentQueryAsync`. Text that does not parse or plan is a `ServiceException` with `InvalidArgument`, its message positioned within the expression (`inline query 1:30: expected ')'`); a planned query that cannot run is a `QueryException`, as a named one's is. The call is refused before anything is sent without the `document_query` and `inline_document_query` capabilities (`Capabilities.InlineDocumentQuery`), and the .NET conformance runner now sends the two inline-query scenarios rather than skipping them.
