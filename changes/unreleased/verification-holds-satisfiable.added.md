- **Verification asks `holds` and `satisfiable`, not only `evaluate`.** The `question` field of `VerifyConstraint`, `VerifyRequirement` and `VerifySatisfaction` puts a constraint, requirement or `assert satisfy` to the service's solvers: `holds` proves the claim for every assignment the free features can take — a requirement's claim being its `assume` constraints implying its `require` ones, the `RequirementConstraintCheck::result` semantics — and `satisfiable` finds one. A `Verdict` stamps `question` and `status`; a violated or satisfiable answer carries `witness` (the free features' replayed values with units and exact spellings), and undecided names the reason — a refused translation, an absent solver, arithmetic the backend could not close, or a rounded unsat that is no proof — through `FAILURE_REASON_UNDECIDED` and `error`. The capability is `verification_questions`, which the Python (`question=`), Go (`opensysml.Asking(...)`) and Java (`VerifyOptions.asking(...)`) clients check before sending.
- **A rounded `unsat` proves only through the rounding-sound encoding.** `holds` asks a violation query whose `unsat` is the claim holding; a query the evaluator's float64 arithmetic rounds is reported proved only when `Query.RoundingSound` rewrites every reachable arithmetic site soundly, and is undecided otherwise — never a false proof.
