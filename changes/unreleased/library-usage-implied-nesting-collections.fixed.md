- The spec-compliance row for the collections a nested usage implicitly subsets (`subparts`, `subitems`, `ownedPorts`, …) no longer says a library's nested usages are left out of them: the runtime has counted them since implicit specializations were derived for every feature, and a conformance case over the Geometry library's `Triangle` and a tier-by-tier test now pin it. The row stays ⚠️ Approximate, restated with what does remain: a nested usage that holds no object (a constraint's Boolean result, a state or subrequirement nothing has performed) and a usage of a library the loader can state no tier for contribute nothing; no behaviour changes.
