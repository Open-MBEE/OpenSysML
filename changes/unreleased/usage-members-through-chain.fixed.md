- The nested features of a calc, constraint or state usage a part definition owns read through a feature chain as any usage's members do (KerML 1.0 §7.4.3; SysML v2 §7.17.2, §7.18.2, §7.19.2): `rig.area.w` and `rig.area.scale` are the input the evaluation bound and the body local it left, `rig.fits.limit` and `rig.fits.margin` the input and local of the check, in a body (`attribute aw = area.w;`), over a declared object (`-e Probe::rig.area.w`) and over a constructed one (`new Rig().area.w`) alike; `rig.area`, `rig.area()` and `rig.fits.result` keep reading as the computation and the verdict. An input nothing supplies — no argument, no default, no same-named feature of the object — reads `<undetermined>` instead of failing, and a member the usage declares nowhere is an `unknown output` (calc) or `no such feature` (constraint) error. A typed state usage whose body declares an entry, do or exit action or a substate (`state sm : M { entry action e; state idle; }`) materializes as its own declaration, so `rig.sm.e` is the entry action it holds and `rig.sm.idle` a member of it rather than `M has no member idle`.
