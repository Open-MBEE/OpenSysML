- The nested features of a calc, constraint or state usage a part definition owns read through a feature chain as any usage's members do (KerML 1.0 §7.3.4.6, §7.4.9.3; SysML v2 §7.19.2, §7.20.2, §7.18.2): `rig.area.w` and `rig.area.scale` are the input the evaluation bound and the body local it left, `rig.fits.limit` and `rig.fits.margin` the input and local of the check, in a body (`attribute aw = area.w;`), over a declared object (`-e Probe::rig.area.w`) and over a constructed one (`new Rig().area.w`) alike; `rig.area`, `rig.area()` and `rig.fits.result` keep reading as the computation and the verdict. An input nothing supplies — no argument, no default — reads `<undetermined>` instead of failing (a constraint usage's unbound `in` no longer reads the owner's same-named feature in its place, and a default reading an unsupplied input — `in y : Integer = x + 1` — is undetermined with it rather than failing on a null, while an unsupplied input whose range admits none still binds empty and the run computes), and a member the usage declares nowhere is an `unknown output` (calc) or `no such feature` (constraint) error. A typed state usage whose body declares an entry, do or exit action or a substate (`state sm : M { entry action e; state idle; }`) materializes as its own declaration, so `rig.sm.e` is the entry action it holds and `rig.sm.idle` a member of it rather than `M has no member idle`. A parameter of a usage nothing has invoked (`part def P { action act { in i : Integer; } }` → `new P().act.i`) reads `<undetermined>` on an instance as it does at model level, instead of the empty value its multiplicity admits: a parameter is bound when its behavior is invoked (SysML v2 §7.17.2). A constraint usage whose default-less `in` nothing binds reads `<undetermined>` naming that input — itself, through `result`, in its owner's body and on a constructed object — instead of failing with `unbound parameter`, as its members already did; a calc usage in that situation reads its `result` as `<undetermined>` too, whatever lower bound the input declares (`in w : Real[1]` no longer fails the read as the unstated form never did; a calc usage's body does not run, and its outputs and body locals read `<undetermined>` naming the input; an analysis or verification usage read as a feature likewise leaves a `[1]` input nothing supplies `<undetermined>` and runs no body on it — its result, verdict and body locals read `<undetermined>` naming the input — while it still runs without a subject, an actor or an input whose range admits none; an invocation that omits the argument, and an analysis run (`-analysis`) that lacks the input, still fail), and the count of an unsupplied input is the parameter's effective range on a constraint as on a calc (`[0..*]` for an unstated `in`).
