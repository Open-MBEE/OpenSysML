- **Use cases execute.** A use case definition or usage is an action definition or usage (SysML v2 §7.19), so it now runs wherever an action does: `sysml -action DroneUseCases::chargeDrone model.sysml` runs its body start to done, `%action`, `%step` and `%tokens` in the REPL drive it, and the LSP debug surface starts it. Its `in`/`out` parameters read as an action's, an `include use case` member performs the included use case as a nested action whose parameters bind from the including one, and its `subject` and `actor` members bind as a requirement's do, so a step reads the objects they are valued with. `-analysis` still refuses a use case, which is no analysis case.
