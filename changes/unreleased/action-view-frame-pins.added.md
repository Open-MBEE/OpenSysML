- **The action view draws the action's own parameters as pins on its frame, and its parameter bindings as edges.** An `action def` or action usage with `in`, `inout`, `out` or `return` parameters — declared, or a usage's inherited from its type — has them as pins on the frame boundary, inputs on the input side and outputs on the output side, as the SysML v2 action-flow notation shows them; a nested parameter's value naming the action's parameter (`in b = bread;`, `in bread = ToastBread::bread;`, `out x :>> x = y;`), an explicit `bind pack.boxed = toast;` and a `bind heat.t = pack.t;` between two nodes' pins are binding edges between the pins, in `dot`, `text`, `mermaid` and `plantuml` and through the service's render surfaces. The lowered `ActionGraph` carries the action's `Parameters` and its pins' `ValueBindings` for every consumer. The text form now lists each node's pins under it and names the pins an edge joins; Mermaid and PlantUML say which pins they cannot draw in a `not represented` notice.
