- `SymbolInfo` now states `Feature::isComposite` and `Usage::isReference` as the model derives them (`is_composite` / `is_reference`, with the metadata flags `composite` / `reference`), so a client tells `part engine` from `ref part driver` — and an end, an `in`/`out` parameter, a `ref attribute` or a port owned by a part from an owned usage — without reading the notation; the Python `Symbol` exposes them as `is_composite` / `is_reference` and in `facts()`, and `children()` / `parts()` take `composite=True` to walk containment past reference usages (`composite=False` for the references). The query API selects and filters `isComposite` and `isReference` beside `isAbstract` and `isIndividual`, over gRPC, REST and OSLC (`sysml:isComposite`, `sysml:isReference`).
