- A part usage typed only by an item definition (`item def I; part p : I;`) is no longer reported as `part-usage-part-definition`, and that diagnostic code is withdrawn. SysML v2 `validatePartUsagePartDefinition` (§8.3.11.3) reads `partDefinition->notEmpty()` over the derived `partDefinition`, which filters KerML `Feature::type` (§8.3.3.3.4) — the union over every subsetted feature, the implied `Parts::parts` subsetting of `checkPartUsageSpecialization` included — so every part usage is typed by `Parts::Part`, implicitly if not explicitly (§7.10), and the constraint cannot fail on a well-formed model. The reflective `type` and `partDefinition` of a usage now join its kind's base definition to the types it declares for every usage kind, as the pilot's own derived properties do.
