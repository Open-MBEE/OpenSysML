- The language server's type inlay hint on a feature written without a typing now states the types the feature inherits from what it redefines, subsets or references (KerML 8.3.3.3.4 `deriveFeatureType`), not the type of its value: `attribute redefines name = "example";` over an `attribute name : Label` shows `: Label` rather than `: String`, and a feature subsetting two typed features lists both. The value's type is shown only when nothing types the feature, and the tooltip says which it is (`inherited type …` or `type of the value: …`). Hover on such a declaration and its completion detail, which showed no type, state the same inherited types. Notebook cells and the MCP `inlay_hints` tool answer through the same code.
