- A succession end in an action body written as a feature chain through an object — `first vehicle.doorClosed then driver.driverReady;` — now executes: the action the part owns is performed on that part where the successions put it, once per chain however many successions name it, and a step the body already states to perform the same chain (`perform action c ::> v.close;`) is the end rather than a second performance. Before, such a model validated in one notation, was reported as `endpoint-not-a-node` in another, and failed at execution with `action succession references undefined source node`. The positional `then v.close;`, the guarded `if g then v.lock;` and `else v.open;` now parse a feature chain as their target, as the grammar's `ConnectorEnd` admits and as `first … then …` already did. A chained end reaching an attribute or an enumeration is reported in every notation (SysML v2 §7.13.5: the related features of a succession are occurrence usages); one reaching an occurrence that is not an action stays valid notation and execution refuses it with a typed error, since no step of the flow performs it.
