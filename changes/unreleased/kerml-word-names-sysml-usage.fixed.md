- A word only KerML reserves — `behavior`, `class`, `struct`, `datatype`, `classifier`, `subclassifier`, `feature`, `step`, `expr`, `bool`, `function`, `predicate`, `metaclass`, `assoc`, `interaction`, `inv`, `connector`, `type` — is now read as the name of a SysML usage whenever a SysML kind keyword precedes it, whatever follows. `action behavior subsets Parts::Part::ownedActions { … }` (the example of SysML v2 §8.4.13.6) declares an action named `behavior`; it was parsed as a `behavior` declaration as soon as a specialization, a multiplicity or a value followed the name, and reported a false `kerml-notation` error in a `.sysml` file. SysML v2 §8.2.2.1.2 does not reserve these words, so each is a legal name there. A declaration that opens with one (`behavior B;`, `feature f subsets g;`) is still reported, and in a `.kerml` file a word only SysML reserves is a name after a KerML keyword the same way (`feature part subsets a;`).
