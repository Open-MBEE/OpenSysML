- **A model parsed by `sysml-grpc` is analyzed once, not once per process.** `ParseSources` and `ParseFile` file the diagnostics a clean-parsing model's analysis reported in the record cache the standard library's records already use, under the model hash, the library's identity and the build; a later process parsing the same documents at the same strictness still parses and indexes them but reads the diagnostics instead of running the validation passes, and answers exactly what a first parse answers. On a 13-document, 541 KB model the first `ParseSources` of a process went from 3.0 s to 0.32 s, and on the 9 documents of `examples/self-model` from 535 ms to 81 ms. A missing, unreadable or mismatched record is a miss and the model is analyzed; the model records of a cache directory are held to 64 MiB together, least recently used first, beside the 30-day idle limit of every record. The runtime tools of `sysml-mcp` and the in-process Go client do the same. `sysml-grpc -no-record-cache` (new) or `OPENSYSML_RECORD_CACHE=0` turns it off. An edited model is still re-analyzed by the process that receives it.
