- A KerML type declaration is now converted as the metaclass its keyword builds, in Turtle and the API's JSON element form alike: `class`, `struct`, `assoc`, `behavior`, `predicate` and `interaction` were written as `sysml:ClassUsage`, `sysml:StructureUsage`, `sysml:AssociationUsage`, `sysml:BehaviorUsage`, `sysml:PredicateUsage` and `sysml:InteractionUsage`, names the metamodel does not declare; `assoc struct` lost its `AssociationStructure`, `classifier` was written as a `Class` and came back as `classifier def`, and `type` as `sysml:ClassUsage`. The `specializes` of each classifier is now a `sysml:Subclassification` whose id ends `_sc<i>`, as a SysML definition's is, where the six keywords above wrote a `sysml:Specialization` at `_sp<i>`; and reflection (`elementId` in a document query) reads that same id, where it read `_sp<i>` for `datatype` and `function` while the conversion wrote `_sc<i>`. **Behaviour change:** the id of the owned specialization of a KerML `class`, `struct`, `assoc`, `assoc struct`, `behavior`, `predicate` or `interaction` moves from `<owner>_sp<i>` to `<owner>_sc<i>`, and its `-id uuid` value with it, on every surface; for `datatype` and `function` the reflected id moves the same way to the one the conversion already wrote. A graph written with the old names still reads.
