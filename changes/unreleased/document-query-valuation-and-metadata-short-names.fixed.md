- A document query can project what a row feature's own value binds: the built-in property `valuation` (KerML `Feature::valuation`) reads the declared or redefined constant — a quantity with its unit, an enumeration literal, a string — or the expression's value evaluated, in `Project` `properties`, `Column(path = …)` and `OrderBy`; a usage bound to nothing or a row that is not a feature — an object row included — is an empty cell. Before, the projectable properties were metaclass properties and member features *of* the row only, so a table over an interface definition's attributes could list names and types but never the bound numbers (`unknown property value`).
- A metadata def in a `<metadata def>::<feature>` property string or `Column(path = …)` is named as `WhereMetadata` names one — by qualified name or by a name unique over the model — so a query beside `metadata def Verification` reads `Verification::method` without spelling the def's full path; an ambiguous short name stays an unknown property. The planner accepts the same spellings as the executor.
- A parameter that writes no value and redefines nothing explicitly reads the binding of the parameter it redefines by position: `action focus : Focus { in level; }` over `action def Focus { in level : Integer = 3; }` gives `level` the value `3` in a document query, as a `properties` member of `focus` and as the parameter row's `valuation`; before, only an explicit `:>>` carried the binding and the cell was empty.
