- The Magic MDK plugin for Cameo gains *Run query*: a `calc def` specializing `DocumentQueries::Query` runs through the service's `RunDocumentQuery` from the browser and diagram context menus, and so does the element of a migrated SysML v1 project whose DocGen table, list or «Document» the migration wrote over such a query — the migration report's targets lead from the Cameo element to the `calc rows : '… Rows'` members of the Document written for it. The query's `in` parameters are asked for before the run, read by their declared type (an element parameter takes a Cameo element by qualified name and starts out as the selected element when it is the only one without a value of its own); the answered columns and rows appear as a table in the results window, every row and element-valued or `qualifiedName` cell selecting its Cameo element on double-click and annotating it, an empty answer is an informational success, and a query the service refuses is one error outcome carrying its message. MDK DocGen gets the matching `RunQuery` extension and stereotype, whose `arguments` tag binds the parameters, rendering each query's rows as a DocBook table under the usual summary (`editors/mdk/README.md` § Run query, `docs/project/mdk-parity.md`).
