- `sysml-mcp -http` no longer lets one authenticated principal read another's unsaved documents: each principal an authenticator names now has a language server workspace of its own, so a buffer held open with `open_document` is read — through the `sysml://workspace/` resources and through every tool — only by the principal that opened it, and another principal reads the file on disk. The local principal and the holder of the bearer token keep the workspace indexed at start; at most 32 other principals hold a workspace at once. Reading a resource (`resources/read`) now requires the `sysml:read` scope and is refused with `insufficient_scope` without it, where before only `tools/call` was checked and a credential with no reading scope could read every workspace and library document.
