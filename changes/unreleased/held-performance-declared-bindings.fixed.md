- Starting or joining a performed action on its performer with an input for a reference parameter the declaration binds (`perform action a : A { in ref :>> context = other; }`) is accepted when the input is that bound object, whether the performance has already started or is still held back by a succession order. A held performance used to accept only the performer itself, since it had no stored binding to compare against; the comparison now evaluates the declared feature value in the performer's scope, without releasing the held performance, and compares by sole element as the started case does. The performer itself is refused where the declaration binds another object, held or started alike. The gRPC conformance cases take a `performer_symbol_id` and `instance_id` inputs for `ExecuteAction`.
