- A behavior with more than one general (`Calculations::Calculation :> Action, Evaluation`) now inherits the parameters each general leaves unredefined, so a calc def's `return` redefines `Performances::Evaluation::result` by position and a verification def's inherited `verdict` masks it: `Evaluation::result` no longer appears beside `r` or `verdict` in the Symbol API's members, `GetElementProperties`'s `feature`, `inheritedFeature` and `directedFeature`, the API JSON export or the REPL (KerML 1.1 §7.4.7.2, §8.3.3.1, §8.4.4.6). A parameter its clause leaves nameless is identified by the name of the parameter its position redefines: `Performances::BooleanEvaluation`'s `return : Boolean` is `Performances::BooleanEvaluation::result`, which a constraint def lists as `result` (KerML 1.1 §8.2.4, §8.3.3.3). A calc def's `return` declared without multiplicity inherits `Evaluation::result`'s `[0..*]`, and reading `result` on a case whose own feature redefines it is refused in favour of the redefiner's name. An action usage containing a `send` statement is no longer implicitly typed by `Actions::SendAction`.
