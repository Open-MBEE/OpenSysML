- A binding connector whose multiplicities link fewer values than its ends hold — `binding [1] bind [0..1] tf.edges = [0..1] tfe` in `ShapeItems::Box`, `binding [1] bind [0..*] base.edges = [0..*] be` in `ShapeItems::Cylinder`, or a user model's `binding [1] bind [0..1] left = [0..1] right` between two collections — identifies some value of one end with some value of the other (KerML 1.0 §7.4.6, §8.3.4.5.2) and determines neither, so reading a bound feature no longer fails with "binding end cannot be resolved": the feature holds what its own declaration states, and the collections it subsets read through it (`Box.tfe`, `Box.tflv`, `Box.vertices`, `Cylinder.be`, `Cylinder.edges`). Validating the object checks each such binding as a `binding` verdict that holds when the ends share at least as many values as the connector links, and is undecided — keeping the object from validating — when an end cannot be resolved.
