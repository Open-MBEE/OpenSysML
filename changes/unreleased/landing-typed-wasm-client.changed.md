- **The documentation homepage runs on the combined WebAssembly module through the typed browser client.** The landing diagram is drawn, instantiated and run through `@openmbee/opensysml/browser`'s `connectWasm` over `sysml-wasm.wasm.gz` built from the tree (`make docs-engine-assets`), in a Worker, instead of a hand-rolled synchronous JSON-RPC adapter over `sysml-engine.wasm.gz`; the module's URL is the single `data-osml-wasm` attribute of the hero, so pointing the site at a published `@openmbee/opensysml-wasm` release is a one-line change. A scene (`editors/vscode/src/landing/scene.ts`) names the model, the drawn view, the shown notation and the state machine the controls run, so a second scene can be added without touching the page's plumbing. The engine and the combined module answer `RenderView` as the protojson `RenderViewResponse` the gRPC service returns (nested `geometry`/`style`, `origin` spans, ports, routes, notes, canvas and rows), the module advertises `render_view`, and `renderedViewFromJson` reads such a saved rendering; the snapshot the page paints before the module loads is that response, regenerated by the same test that proves the module parses, renders, instantiates and runs the model. The showcase state machine's first state is `begin`, so it no longer shadows the standard library's `StateAction::start`.
