- A feature valued by an expression (`attribute y : Integer = x + 1`), computed as it is read, now carries the order-dependence marks of what its expression reads at that moment, through features so valued in turn, and a write computed from it (`assign z := y + 10`) stands on those choice points as a write from `x` would. Such a value was reported bare after racing writes of `x`, and so was everything written from it, although `explore` showed the set.
- The SMT engine (`-engine smt`) refuses an action declaring a feature valued by an expression over other features instead of encoding it as the value it held at the start, which proved results the run does not reach.
- A redefining feature that declares no value (`attribute :>> y;` over `attribute y : Integer = x + 1`) is bound as the feature it redefines is: its value follows `x` as it is read, where it was evaluated once as the performance started, and it carries the marks of what the inherited expression reads.
