- **The WebAssembly gzip size budgets rise by 50 KB.** The gzipped js build of `sysml-wasm` is now bounded at 8,350,000 bytes and that of `sysml-engine` at 7,700,000 bytes. Exact Rational number support grew both binaries past the previous bounds of 8,300,000 and 7,650,000 bytes (the combined build measured 8,309,493 bytes gzipped, the engine 7,647,486), so `TestWasmRuns` failed on the integration branch itself; the budgets bound growth only, and `TestEngineDependencies` still catches a forbidden dependency.
- **The WebAssembly gzip size budgets now bound gross growth only.** The gzipped js build of `sysml-wasm` is bounded at 10,000,000 bytes and that of `sysml-engine` at 9,000,000 bytes. The size as it stands is accepted: the grid view and relationship matrix grew the combined build to 8,355,865 bytes gzipped and the engine to 7,686,608 on the integration pipeline, over the 8,350,000-byte budget set a step earlier (a GitHub runner builds the same tree about 11 KB smaller, 8,344,612 and 7,686,149, so the pull-request gate passed while every integration pipeline failed `TestWasmRuns`). The budgets no longer move in 50 KB steps with each feature; `TestEngineDependencies` is the gate that keeps a forbidden dependency out of the engine.
