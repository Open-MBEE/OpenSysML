- `istype`, `@`, `hastype` and `as` judge an object by every type it inherits through the feature holding it (KerML 1.0 §7.3.4.3–§7.3.4.4), not its stated type alone: with `item front : Panel :> faces` in an `item def Rig :> Objects::StructuredSpaceObject`, `rig.front istype Objects::StructuredSpaceObject::StructuredSurface`, `rig.front istype Objects::Surface` and `rig.front @ Objects::StructuredSpaceObject::StructuredSurface` are `true` and `rig.front as Objects::Surface` yields the object, where each answered `false` or `()` before although the object already carried `StructuredSurface`'s `edges`. `hastype` names the direct types only (KerML 1.0 §7.4.9), so `rig.front hastype Panel` and `hastype StructuredSurface` are `true` and `hastype Objects::Surface` stays `false`, and a `Panel` held by nothing that subsets `faces` is still no `StructuredSurface`.
