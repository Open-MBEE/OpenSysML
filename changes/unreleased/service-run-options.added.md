- The service and `sysml-mcp` take the run options the CLI already had: `DiagnosticsRequest` selects lints (`disable_lint`, `enable_lint`, as `-disable-lint`/`-enable-lint`), `ExecuteActionRequest` and `ExecuteStateRequest` carry `advance`, `seed`, `draws` and `clock_step` (as `-advance`, `-seed`, `-draws`, `-clock-step`), `RunAnalysisRequest.tool_dry_run` previews the first external tool call as a typed `ToolDryRun` instead of running it (as `-tool-dry-run`), and `ListEnginesRequest.probe` starts each external engine and checks its handshake (as `-probe`); a malformed option is an `invalid_argument`. The Python, Node, Java, Rust, Julia and MATLAB clients expose the same options — the run options on their action and state executions, `tool_dry_run` on their analysis runs with the typed `ToolDryRun` preview on the result, `probe` on their engine listings and the lint selection on a diagnostics call (`Model.refresh_diagnostics` in Python, `Model.refreshDiagnostics` in Node and MATLAB, `Model.diagnostics(DiagnosticsOptions)` in Java, `Connection::diagnostics_with_lints` in Rust, `refresh_diagnostics` in Julia) — and read the clock a run stopped at back out of a failure; the Go client selects lints with `WithDisableLint`/`WithEnableLint`. The gRPC and client conformance cases cover them, and the catalog's unserved list shrinks by those flags and `-samples`, which `RunSweepRequest` already carried.
