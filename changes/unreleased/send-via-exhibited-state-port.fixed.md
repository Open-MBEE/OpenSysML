- `send … via p` from a state machine whose definition owns `port p`, exhibited by a part, now leaves through the performance's port as the model binds or connects it: a `bind m.p = p` or `:>> p = Part::p` on the exhibit usage sends through the part's port, and a connector written against the performance's port (`connect m.p to q`) carries the message; before, the send failed with "joined to no port that can receive it" however the state's port was bound. A state port nothing binds or connects is still unroutable, as its namesake on the part is another feature. A transition's `accept … via q` on a port the state definition owns, when the exhibiting part has no port named `q`, now receives what reaches the performance's port through its binding or a connector written against it, instead of never firing.
