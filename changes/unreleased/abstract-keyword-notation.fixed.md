- An abstract definition or usage is now named with its written `abstract` keyword in every rendering — `«abstract part def»`, `«abstract part»`, `«abstract datatype»` on tree, interconnection and mixed diagrams in text, Mermaid, DOT, D2, PlantUML and the editor's diagram payload, in the kind column of element tables, in hover, completion, REPL kinds and solver verdicts (`Abstract part fam permits …`) — where it was drawn as a plain `«part def»`/`«part»`, indistinguishable from a concrete element (SysML v2.1 §7.6.2, §7.6.3, Table 4). A variation keeps `«variation …»` alone, since the specification says a variation is always abstract and the keyword is not written on it (§7.6.7). The kind keyword behind a modifier still decides what a kind-keyed rule reads: an abstract KerML classifier such as `Base::Anything` still types a part, an abstract definition is still drawn in the definition shape and fill, and a moved `abstract part` is still admitted where a part is.
