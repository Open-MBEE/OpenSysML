- **`ExecuteState` and `ExecuteAction` on a performer report the performer's attributes.** A behavior run with `performer_symbol_id` (`performer=` in the Python client) already took its guards and expressions against the performer's feature values and wrote the performer, but an executed response carried only the behavior's own values, so two performers leaving different values looked alike. `ExecuteStateResponse.final_context` now holds the performer's attributes under `this.` (`this.speed`, `this.seen`), as an explored outcome's `outputs` already did. `ExecuteActionResponse` gains `performer_attributes` (field 7) with the same entries, leaving `outputs` the action's output parameters alone; the clients expose it as `ActionRun.Performer` (Go), `ActionRun.performer()` (Java) and the `performer` attribute of the `ActionOutputs` dict `execute_action` returns (Python). Without a performer neither response changes.
