- **A merge node passes every token that reaches it, so a loop through a merge runs to its exit.** The action executor used to record one traversal per merge for the whole run and retire every later arrival, so the specification's `ChargeBattery` loop stopped after one pass (`level = 50`, `passes = 1`) without ever performing `endCharging`. A merge is now one `MergePerformance` per arrival, as `Actions::MergeAction` declares: its body runs and the token is forwarded on every traversal, a loop re-enters it as often as its guard sends the token back (`action_merge_loop_reenters` leaves the known failures with `level = 100`, `passes = 3`), and a fork whose branches both reach a merge yields one downstream token per branch, as two merge performances do — collapsing them is a join's job. A merge is also the one multi-incoming node the join synchronization does not wait at. Termination of a loop with no exit is the action step budget's job as before: `ErrActionStepLimitExceeded`, under `RunToCompletion` and under the REPL's `%continue` alike.
