- **A migrated view qualifies the references its own `expose`s would capture.** Each `expose` imports the exposed element's name into the view, where every reference in the view's body resolves before the enclosing scopes do (KerML 8.2.3.5.3, local resolution includes imported memberships). A diagram showing a definition beside a same-named usage, such as a block `GUI` and a part `GUI` typed by it, wrote `expose GUI` and `Layout about GUI` for the definition, which inside the view denoted the usage: the usage's layout was reported as already stated, the definition was left without a position and undrawn, and the associations ending at it fell back to stray boxes. The writer now treats the names the exposes import as the view's own and spells out the full name of what a simple one would no longer denote, for the `expose` targets themselves and for every Layout, Route, Style and Note `about` in the body; a name one expose imports by its simple spelling is written as before, so output changes only where it was ambiguous.
