- A symbol's type facts now carry the types the feature derives (`TypeInfo.types`, KerML 8.3.3.3 `Feature::type`, the `type` property of `GetElementProperties`), so a feature typed only through subsetting (`part pSub :> q`), reference subsetting (`ref part pRef ::> q`) or redefinition (`attribute :>> a = 3.5`) reports the subsetted feature's types, and `part pBoth : V :> q` reports `V` and `T`; `declared` and `resolved_id` stay the typing as written. Reference subsetting (`::>`, `include`) is reported among `specializations` as kind `references`, which it was left out of. The SymbolInfo field docs and the Python, Go, TypeScript, Java, Rust and Julia `Symbol` docs say what `kind`, `metadata["direction"]`, `type_info` and `specializations` summarise and name the `element_properties` property that defines each. The Python, TypeScript and Julia class generators take a feature's type from the service's derived types, walking its specializations only against a service that predates them.
