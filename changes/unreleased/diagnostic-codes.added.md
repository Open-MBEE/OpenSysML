- Every diagnostic now carries a stable, kebab-case code, registered in `internal/check/codes` with what it means, how to resolve it and the specification clause or validation constraint behind it: the bucket codes `type` and `type.expr` are replaced by one code per rule (`relationship-target-kind`, `binding-connector-type-conformance`, `operator-operand-type`, `invocation-argument` …), the parser names each misplaced-member rule after its owning-type constraint (`subject-membership-owning-type` …), and name resolution codes its findings at the source. `sysml -explain <code>` prints a code's explanation and `sysml -explain` lists them all; the REPL offers `%explain-code <code>`, sysml-mcp an `explain_diagnostic` tool, and the language server publishes a `codeDescription` link beside each diagnostic's code. Text diagnostics read `file:line:col: error[code]: message`, so the code sits in a stable, parseable position; `-json` already carried it. The catalogue in docs/reference/diagnostics.md is generated from the registry and `make diagnostics-check` fails when it drifts, and a sweep test over every model in the tree and the standard library proves each emitted code is registered.
