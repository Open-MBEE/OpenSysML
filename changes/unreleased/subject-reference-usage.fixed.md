- A `subject` is now a `referenceUsage` of direction `in` typed as written (SysML v2 §8.2.2.19 SubjectUsage, §8.3.21.11 SubjectMembership, KerML §8.3.4.6 `parameterDirection`), whether it is declared in a requirement body or in a case body, on the symbol `kind` and `metadata`, the query `@type` and the reflective metaclass alike; before, a subject was a `partUsage`, a requirement's subject carried no type and a case's subject no direction. The parameters a behavior inherits from the library — the `result` of a case or requirement, the `verdict` of a verification case — are now listed among its members like a declared `return r`, instead of being withheld with the library members; a declared `return` still masks the inherited parameter it redefines.
