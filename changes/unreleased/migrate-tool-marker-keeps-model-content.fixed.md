- `sysml -migrate` no longer discards model content a modeling tool's profile marks. A stereotype of any of the tool's own profiles (`SimulationProfile`, `DSL_Customization`, `UI_Prototyping_Profile`) on a model or package — Cameo's «NumberOwner» numbering settings on the root model, for one — used to skip it and leave every element below unmapped, so the migration wrote an empty model. Such a stereotype now makes an element the tool's own only when it extends the element's own metaclass and the element neither has nor owns, at any depth, a standard stereotype, a behavior or a package; everything else migrates, the stereotype kept as an `AppliedStereotype` marker.
