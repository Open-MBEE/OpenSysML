- `RenderView` writes a view as diagram or table source, not only as data: `RenderViewRequest.form` (`text`, `mermaid`, `markdown`, `dot`, `plantuml`, `d2`, `drawio`, `csv` or `tsv`) answers the rendering in `RenderViewResponse.text`, byte for byte what `sysml -render <view> -render-form <form>` writes, under the writer options `palette`, `style`, `lines`, `direction`, `link` and `unplaced`; an unknown form or one the view's kind is not written in is `INVALID_ARGUMENT` with the CLI's message. The service, the JSON engine (`sysml-engine`, `sysml-wasm`) and `sysml-mcp`'s `render_model_view` serve it under the new `render_view_form` capability. The Go client gains `WithForm`, `WithPalette`, `WithStyle`, `WithLines`, `WithDirection`, `WithLink`, `WithUnplaced`, `RenderedView.Text`, the `ViewForm…` constants and `ViewForms()`, and `WithDocumentForm` so `RenderDocument` answers HTML or AsciiDoc; the Python client's `render_view` takes `form` and the writer options and answers `RenderedView.text`.
