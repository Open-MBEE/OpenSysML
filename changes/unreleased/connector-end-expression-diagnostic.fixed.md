- **Report an expression written as a connector end once.** `connect [1] s.y#(1) to [1] k.u;` used to produce four errors for the one mistake — `expected 'to' between connector ends`, `expected '{' or ';' after declaration`, `expected a metadata feature name after '#'` and `expected a body member`. A connector end is a feature chain (SysML BNF 8.2.2.13.1) and `#(…)` is an expression operator, so the model is still rejected, now with the one diagnostic `a connector end names a feature, not an expression; name the feature itself and put any multiplicity before it` at the end, and the parse resumes at the next end or the end of the declaration. Element selection `#(…)`, indexing `[…]`, `->` invocations, `.?`, arithmetic and calls are all recognised, in `connect`, `connection`, `interface`, `allocate`, `succession`, `bind` and `flow` ends alike.
