- **`sysml-mcp` tool catalog.** One catalog (`internal/frontend/mcp/catalog`) now names every tool the server serves, the group that serves it, the `sysml-grpc` RPC and `sysml` flag it stands for and a one-line summary. The new `tool_catalog` tool answers it to a client, narrowed to the groups served, and the Tools section of `sysml-mcp(1)` is generated from it, so neither can drift from the tools registered. Drift gates pin the catalog to the code: every RPC of `api/proto/sysml.proto` must have a tool or be listed, with a reason, among the RPCs that must not be tools; the tools a group registers must be exactly the catalog's; and every `sysml` flag must be classified once, as the tool that performs it, as an operation the service does not serve yet (with what it lacks), or as CLI-only (with why). The runtime group gains `model_diagnostics`, the `GetDiagnostics` RPC, which reports every diagnostic of a parsed model as `sysml -validate` does, strict mode included through `strictConformance`.
