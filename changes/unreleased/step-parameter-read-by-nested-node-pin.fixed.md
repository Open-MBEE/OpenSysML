- A parameter a `perform` usage's body restates (`perform action run : Sequence { in sysLimit = 6.8; }`) implicitly redefines the parameter at its position of the performed action, so a model-level read through the performance of a nested node's pin valued from it (`action decision : Decide { in limit = sysLimit; }`, read as `run.decision.limit`) now holds the supplied value instead of an empty sequence, and an output default over that pin (`out go : Boolean = limit <= 10.0;`) evaluates instead of failing the materialization of the performer with a `type mismatch` over the empty operand; the performance itself already ran the node with the value.
