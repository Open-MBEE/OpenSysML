- `sysml -validate` no longer fails over a model whose `rep language "asciidoc"` bodies need a converter the host lacks: a missing markup converter is now the warning `document-plan-markup-tool-missing` at the document's first such body, naming the converter looked for, whether `OPENSYSML_ASCIIDOCTOR` named it or it was the default looked up on `PATH`, and the remedy, and the rest of the document is still validated with those bodies unchecked (`-warnings-as-errors` makes it a failure). A converter that is found but fails stays the error `document-plan-markup-tool-failed`, and rendering a document still fails when its converter is missing, since the rendering needs the body. A document reported on its converter being missing or failing writes no interface record, so installing the converter is seen on the next run rather than hidden by a cached verdict.
