- The pull-request workflow's changed-areas filter and protobuf wire-compatibility check diff a merge-queue group from its merge base with the base branch, no longer from the group's `base_sha`. Inside the queue that `base_sha` is the group commit of the entry queued ahead, so a group whose last entry touched one client ran only that client's jobs: on 2026-11-17 such a group skipped the Go shards and the WebAssembly size gate and merged four entries ahead of it whose own groups had failed that gate. `tests/hygiene` now refuses any read of `merge_group.base_sha` in the workflow.
