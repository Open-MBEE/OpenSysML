- **A model can read whether a state usage is active: `fill.isActive`.** The bundled non-normative `StateActivity` library (`OpenSysML Libraries/StateActivity.kerml`) declares `isActive : Boolean[1]` as a derived feature `featured by States::StateAction`, so after `private import StateActivity::*;` any state usage reached by name or feature chain reads `x.isActive` from a guard, a constraint, an `assert constraint`, a calc, an assignment or a parent or sibling state's behavior. It is `true` exactly while the state is in the active configuration of the machine running it — a composite while any substate is, a parallel region's state together with its siblings, the state itself during its own entry and exit actions — and `false` while a transition's effect runs (its source has exited, its target not yet entered, so a self-transition's effect reads `false`), before the machine starts and after it ends. The value is read from the executor's active configuration; a write to it is refused as a write to any derived feature is, and the code generator reports such a read as not compilable. Neither `States.sysml` nor `StatePerformances.kerml` declares the feature, so without the import `x.isActive` stays `unresolved member` as before, the import is reported as `nonstandard-notation` (an error under `-strict`), and completion and hover on `x.` offer and type it only under the import.
