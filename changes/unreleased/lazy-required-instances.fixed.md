- **Hold a large or expression-valued lower bound without allocating it.** A feature whose lower bound is past 1 000 (`part p : C[5000]`), or given by a model-level evaluable expression (`C[k * 1000]`, `C[n..*]`), now holds exactly that many values instead of reporting a multiplicity violation: the identities are reserved up front and each object is made when it is first read, indexed, iterated, written or bound, so `size(p)`, `p#(i)`, `includes`, iteration, `all T`, snapshots, held images, the explorer's state key and the RDF/JSON/gRPC object listings all see the same values under stable identities. Work that must reach every value is charged to the element budget (`OPENSYSML_MAX_ELEMENTS`) and refused with `ErrElementLimitExceeded`; a lower bound of `*` (`[*..*]`) remains `ErrInfiniteLowerBound`, a multiplicity violation naming KerML 1.0 §7.4.12.
