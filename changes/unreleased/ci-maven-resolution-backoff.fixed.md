- A Maven build in CI no longer fails on the first HTTP 429 burst from Maven Central. Each Maven tree (`client/java`, `editors/mdk`, `editors/syson`) carries a `.mvn/maven.config` that raises the resolver's retries on a 429 or 503 from three to eight (about three minutes of backoff, or what `Retry-After` asks), under both the property Maven 3.9 reads and the one Maven 3.10 reads; `scripts/download-pilot-validator.sh` passes the same to the pilot's build. A new workflow, `.github/workflows/maven-cache.yml`, resolves the three trees on each push to `develop` that changes a `pom.xml`, and daily, and alone saves the dependency cache; the Java jobs restore it through `.github/actions/maven-cache` in place of `actions/setup-java`'s per-branch cache, so pull requests and merge groups start warm rather than each resolving from Maven Central. `tests/hygiene` holds both in place.
