- **`holds` and `satisfiable` follow the evaluator's short-circuit order over a declared value that does not evaluate.** A feature whose default fails to evaluate (`attribute bad : Real = 1.0 / 0.0;`) no longer leaves every question naming it undecided: the translation tracks the left-to-right evaluation path of `and`, `&`, `or`, `|`, `implies`, conditionals and ordered conditions, so `true or bad > 0.0` holds and is satisfiable as `evaluate` says, while `bad > 0.0 or true` and `true xor bad > 0.0` stay undecided because the evaluator reads `bad` first. A feature reached only under some assignments (`free > 0.0 or bad > 0.0`) is guarded rather than left free: a witness or counterexample avoids it, and a proof is claimed only when no assignment reaches it — otherwise the verdict is undecided, naming the feature read `under some assignment of its free features`.
