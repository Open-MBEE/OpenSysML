- Every `Multiplicity` now has the implied specialization the specifications require: a written range (`[2]`, `[0..*]`), a KerML `multiplicity` member and the implicit `[1..1]` a usage states subset `Base::naturals` (KerML 1.1 §8.3.3.1.9 `checkMultiplicitySpecialization`), which types them `ScalarValues::Natural`; the empty `Multiplicity` an `individual` occurrence, part or item definition is parsed with (its `Type::multiplicity`, first among its owned memberships) subsets `Base::zeroOrOne` (SysML v2 §8.3.9.3 `checkOccurrenceDefinitionMultiplicitySpecialization`). The semantic model serves the general through `DirectSupertypes`, `ImplicitGenerals`, `FeatureTypeSet` and `type`. A multiplicity member whose declared `subsets` already reaches `Base::naturals` takes no implied one. The pilot's further defaults — `Base::exactlyOne` for a `Multiplicity` a feature owns and `Base::zeroOrOne` for one any classifier owns — are not implied, as no clause requires them.
