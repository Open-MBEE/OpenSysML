- **A swimlane of an action flow can be placed.** Dragging a swimlane in the VS Code diagram panel was refused with `<view> does not expose <part>, so a Layout in its body would place nothing`, because the view exposes the action and not the part performing it. A `Layout` about the performer in the view now places the lane drawn for it, with the nodes it holds inside, in the panel and in every rendering. The panel also says why a node does not move when it is dragged: `start` and `done`, which a behavior inherits from the standard library, and a performer listed in a `performed by` compartment, which no longer offers a drag that was refused. One `Layout` places one of a performer's lanes in a view, the outermost and then the first in the view's order, whether or not a folded flow hides it, so folding or moving one lane never moves another; the panel offers a drag only for that one and says so on the others. An edited draw.io file imports a placed lane the same way: moving it writes the `Layout` about its performer, and resizing a flow no `Layout` places keeps the lane and the nodes placed in it where the file shows them. The language server holds to that rule whatever the client: a `setLayout` about a performer with several lanes in the view names, as `within`, the action the dragged lane is drawn in, and one that names no lane or another lane is refused, so an older panel cannot move a lane it did not drag. A rendering of no declared view is held to it too: there the `Layout` is written inline, and a `setLayout` about a performer that performs in several actions also names, as `rendering`, the pseudo-view the lane was dragged in.
