- A `*` written as a feature value is typed as the Positive KerML makes it (`checkLiteralInfinitySpecialization`), so `attribute b : Boolean = *;` and `attribute s : String = *;` are reported as `binding-connector-type-conformance` errors, as a string bound to an Integer is, while `Natural`, `Positive`, `Integer`, `Rational` and `Real` targets still take it; it counts as one value under `feature-value-count`, so `(1, *)` fills an `Integer[2]`. Before, the value's type was unknown and such a binding went unchecked.
