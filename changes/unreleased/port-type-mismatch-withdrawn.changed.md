- **The `port-type-mismatch` lint is withdrawn.** It warned on a `connect`, interface usage or `flow` between ports whose definitions were unrelated and whose directed features were not conjugate, conflating unrelated with incompatible: neither KerML 1.1 §8.3.4.5.3 nor SysML v2 §7.12.2, §8.3.13–8.3.16 constrains the types at the two ends of a connector against one another, and the pinned pilot validator reports nothing on such a model. The one provably empty case, an end of a connector typed by an interface or connection definition whose end type is disjoint from the connected port's definition, is a feature typed by disjoint types and is reported by `disjoint-feature-types`, which now names such an end by its connector and the feature it attaches to (`the end of this interface at y.p3`) instead of by its empty name. `-disable-lint port-type-mismatch`, `%lint port-type-mismatch off` and `disabledLints: ["port-type-mismatch"]` now reject the code as unknown. Refs #1887.
