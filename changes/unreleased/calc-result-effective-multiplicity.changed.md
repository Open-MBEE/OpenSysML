- **A calculation result with no stated multiplicity is held by its effective multiplicity, as an action's parameters are.** A bare `return : Real` (or a result inherited from the calculation definition) is a reference usage, so SysML §7.6.3 gives it no implicit `[1..1]`: its effective multiplicity is the `[0..*]` of `Performances::Evaluation::result` it redefines (SysML §7.19.2, KerML §7.3.4.2), and one computed value is held as a one-element sequence on every surface — `%calc`, `%eval`, `%analysis`, `%sweep`, `%runs`, `-json`, traces, gRPC `EvaluateCalc`/`RunAnalysis`/`RunSweep`, the MCP tools, export and the clients. `return : Real` now answers `[0.75]` where it answered `0.75`; `return : Real[1]` and `return : Real[0..1]` still answer `0.75`, and an explicit `[0..*]` or `[2]` is unchanged. A test or client reading one value writes `return : Real[1]`, or takes the sole element. A body-local attribute, item or part usage stating no multiplicity holds the one value such a result gives it, its implicit `[1..1]`; an input parameter is bound as its argument came.
