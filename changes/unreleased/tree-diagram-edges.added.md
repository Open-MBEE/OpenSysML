- **A tree rendering draws the relationships between the elements it shows.** `asTreeDiagram` views — the default rendering, and what every migrated SysML v1 block definition, class and package diagram becomes — now carry the edges a general view draws between their nodes: a specialization, subsetting or redefinition to each drawn general (hollow triangle at the general end), a composition (filled diamond at the owner) or reference (hollow diamond) from an element to the definition typing each part, item, port, attribute or `ref` usage it owns, labelled with the usage's name and multiplicity, and the typing of a usage whose owner is not drawn. An edge is drawn only between two drawn nodes, never into a nested one, and a usage's `Route` steers the composition standing for it; a specialization or typing has no member of its own and is routed by the client. The `text`, `mermaid`, `dot`, `plantuml` and `d2` forms, the `opensysml/render` response and the VS Code diagram panel, with new hollow-triangle and diamond markers, all show them, so a migrated BDD's generalization and association lines are drawn between the blocks it exposes.
