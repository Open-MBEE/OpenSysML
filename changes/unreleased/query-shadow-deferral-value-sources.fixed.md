- A filter on a name shared by a model feature and a built-in now decides whether the name is shadowed from the rows the query started with, so reversing the terms of an `and` no longer changes whether an operand is accepted; it defers an incompatible value only when that value was read from the built-in, including when the shadow is declared by a state, verdict, event or object row.
- A computed column named like a built-in or a model property is compared from its cells, so an incompatible cell no longer inherits a shadow from the unused model path: a matching cell survives, and a column with no comparable cell reports the operator error. A text feature compared with an ordering operator reports the error instead of returning no rows. Explicit `@` built-ins keep strict validation.
