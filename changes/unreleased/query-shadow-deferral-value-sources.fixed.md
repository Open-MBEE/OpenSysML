- A filter on a name shared by a model feature and a built-in now decides operand validity from the rows the query started with, so reversing the terms of an `and` no longer changes whether an operand is accepted. An incompatible built-in value may defer to a shadowing feature; an incompatible declared value under a shadowed name is skipped when another starting row supplies a comparable value. A name with no comparable value still reports the operator error, and an explicitly selected `@` built-in stays strict.
- A computed column named like a built-in or a model property is compared from its cells, so an incompatible cell no longer inherits a shadow from the unused model path. A valid comparison that returns false counts as a comparable cell: a mixed column with only nonmatching numbers now returns no rows instead of reporting the operator error, while a column with no comparable cell still reports it.
- Values read through a direct projection keep their source. One numeric feature no longer hides an invalid ordering comparison on a text feature of the same name; filtering before and after projecting a declared feature now agrees.
- An explicit `@annotations` read on a held object no longer probes a feature of the same name, so a lazy part is not materialized and its classifier behaviors do not start. A projection of a declared feature through a state, verdict or event row keeps the terminal value's built-in provenance, including a dotted read.
- A union establishes its emitted rows as the scope for filters above it. A row an arm filtered out no longer supplies operand evidence, so an empty arm cannot turn an invalid built-in operand into a silently empty result.
- A scoped filter on a built-in name shadowed by a model feature now compares the path's final property and skips a related element whose value cannot take the operand, so the rows whose feature matches are returned instead of the whole query failing. A native document query filtering bare `isActive` with a non-Boolean operand now reports an invalid-value error when no model feature shadows the name, instead of silently returning no rows.
