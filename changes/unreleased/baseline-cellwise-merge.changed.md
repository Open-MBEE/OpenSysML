- Two pull requests that each move a count of a generated baseline no longer have to re-run the pilot to land. `derived-census -recorded-pilot` measures this repository's side alone against the pilot column the committed records hold (pinned by a new `pilotRecords` digest in the baseline), and the pull-request workflow now runs it as `-check` on every Go change, where no workflow reproduced the census before. `pilot-apijson-diff -pilot-record DIR` keeps the pilot's export per root, keyed by the pin, the declared Java, the bridge, the errata, the root and the libraries, and replays a matching one without Java; CI restores the export the nightly oracle-reproduction workflow records, and the nightly also re-exports the census's pilot column. The count baselines merge cell by cell (`tools/cmd/baseline-merge`, configured in a clone by `./scripts/install-baseline-merge-driver.sh` and used first by the `ci:rebaseline` workflow), and a merged baseline is kept only when its check reproduces it. The cross-MDK conformance suite (`hideo-suite -check`), reproduced only nightly until now, also runs on every pull request that changes Go or the Python client; its baseline records the twelve element-property cases (`B13-055` to `B13-057`, `B13-073` to `B13-075`, in both property readers) that the positional `then` relationship-ends fix moved from fail to pass.
