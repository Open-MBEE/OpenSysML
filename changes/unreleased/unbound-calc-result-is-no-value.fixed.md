- A calculation whose result parameter is never bound — a body with no result expression or `return`, or one that runs to its end without returning — is now reported as *no value* (`ErrNoValue`), the same error an `out` parameter the body never assigns reads as, instead of the distinct `no result expression` / `calculation returned no value` errors. KerML 7.4.8.2 and SysML 7.19.2 say only how a result *is* bound, so a result nothing binds has no value asserted; it is not a separate kind of failure. The diagnostic's detail is unchanged: it still names the calc and, for a `return h;` that binds nothing, the two forms that state a computed result. Every surface that reports a calc's error (REPL `-calc`/`-e`, LSP, gRPC, MCP, the analysis engines and the compiled statement path) carries the new wording, e.g. `no value: calc test::maybe ended without a return`.
