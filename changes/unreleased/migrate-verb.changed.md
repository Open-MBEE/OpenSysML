- **`-convert` refuses a SysML v1 model; it is migrated, not converted.** `sysml Model.mdzip -convert sysml`, whether `-from xmi|uml|mdzip` or the `.xmi`, `.uml` or `.mdzip` extension names the input, now exits non-zero with ``sysml: Model.mdzip is a SysML v1 model, which is migrated, not converted: every element is mapped, approximated or left unmapped and reported element by element; write `sysml Model.mdzip -migrate sysml -o Model.sysml -migration-report Model.report.txt` ``, since readers took `convert` to mean lossless and the migration accounts for every element instead. The service's `Convert` RPC refuses the same input with the same message (`INVALID_ARGUMENT`), and so do the Go, Python and Java clients' `convert` methods, each naming their `migrate`. **Breaking** for a script that ran `-convert` on v1 input: replace `-convert` with `-migrate` on that command line — the output is unchanged — or `convert(...)` with `migrate(...)` in a client. There is no alias and no deprecation period.
