- `GetSymbol` now names the metadata usages annotating an element in `SymbolInfo.annotating_metadata_ids`, the inverse of KerML 1.1 §8.3.2.3 `AnnotatingElement::annotatedElement`: the ones the element owns, written as a `#M` prefix or as `@M` / `metadata m : M` in its body, then the ones naming it in an `about` clause anywhere in the workspace (`metadata pumpA_fm : FailureMode about PumpA { severity = 2; }`), which were not reachable from the annotated symbol before. Each id answers `GetSymbol` with the usage's type and attribute values. An `about` usage is an owned member of the namespace it is written in, so `child_ids` and `members` keep leaving it out. Advertised as the `symbol_annotating_metadata` capability and read by `Symbol.annotating_metadata()` in the Python client, `Symbol.AnnotatingMetadataIDs` in Go, `ModelSymbol.annotatingMetadataIds` / `annotatingMetadata()` in Node, `Symbol.annotatingMetadataIds()` in Java and `Symbol::annotating_metadata_ids()` / `annotating_metadata()` in Rust (#2203).
