- Every occurrence that began has its start shot, so reads that answered the static shape alone now answer the run: `start`/`startShot` on an instantiated object is a snapshot object rather than `<undetermined>`, `snapshots`, `timeSlices`, `portions`, `timeEnclosedOccurrences`, `spaceTimeEnclosedOccurrences` and `spaceEnclosedOccurrences` list the shots that happened (a time slice takes all of the occurrence's space, so a shot is space-enclosed too) and are open until the occurrence ends, `successors` is undetermined until it ends, and `predecessors` lists what ended before it began; `Clocks::TimeOf`/`DurationOf` return bare numbers where they returned quantities of seconds. Runs materialize more objects — a `Transfers::Transfer` at every send, the accepting performance at every accept, a snapshot on the first read of a shot — so object numbers in `-trace` output, `-engine check` reports and gRPC instance ids shift after them.
- A shot carries the values its occurrence held at that instant: an ended occurrence's end shot reads its values, and a start shot reads the values nothing assigned since the start; one assigned since is undetermined on the start shot, saying the value then was not recorded.
- A message a state machine takes only to drop it (no transition accepts it) leaves its `Transfers::Transfer` unended; a `send … to` from a performed action lists the transfer under that performance's `outgoingTransfers` as a `via` send does.
