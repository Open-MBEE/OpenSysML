- A query reads the `elementId` of the expressions a statement of an action body writes: an assignment's target and value, a loop's conditions, a `for` loop's collection, an `if` condition, and the target of a `perform` or `terminate`, with their operands, parameters and memberships. They are reflected as elements of the statement but read no id, so a query keying `LiteralInteger`, `OperatorExpression` or `FeatureChainExpression` by `elementId` found unkeyed rows wherever a model held one. The id is the one a conversion writes (`A___400_pvalue`, `A__n_pcollection_pa0`).
- A `for` loop written as a named action node (`action n for i in 1..3 { }`) no longer reflects its iteration variable as a second owned member holding a copy of the collection expression under the same `elementId`; the variable stays the loop's `sysx:loopVariable`, as it is for an unnamed loop.
