- **`sysml -validate` reports for a CI service.** `-format sarif` writes the run's diagnostics as SARIF 2.1.0 — one run, the tool's name and version, one rule per diagnostic code, each finding's severity as its level, its file relative to the working directory with line and column, and the fixes analysis offers — for GitHub code scanning and the other SARIF readers; `-format junit` writes JUnit XML with one testsuite per file, one failing testcase per finding and a passing one for a file with none; `-format json` is `-json`. A document goes to stdout or to the file `-o` names. `-baseline <file>` reads back a JSON report `-validate -json -o` wrote as the findings already known and suppresses each finding with the same code, file and message, whatever line it moved to, from the report and the exit status, saying how many it left out. `-warnings-as-errors` ends the run on a warning as on an error while the report keeps the warning's severity. The same SARIF and JUnit writers now serve the pilot-differential referee, from `internal/frontend/report`.
- **A composite GitHub Action, `Open-MBEE/OpenSysML@<tag>`,** installs that release's `sysml` with the install scripts, runs `-validate` over a path in the chosen format and, for SARIF, uploads the report to code scanning; the repository's workflow runs it over `examples/`.
