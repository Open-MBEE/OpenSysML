- **A transient `ParseSources` answer no longer has to displace the model a caller holds.** With the new `parse_sources_keep` capability a client can set the presence-bearing `keep` field to `false`: the service answers the same model hash, roots, diagnostics and affected set as a kept parse but neither inserts the model into its parsed-model cache nor looks up an entry already under that hash, so a derived union read for its results cannot evict or promote the caller's open model. Omitting the field gives the old kept parse byte for byte and needs no capability; because the field is presence-gated, an explicit `keep=true` also requires `parse_sources_keep` and is refused with `UNIMPLEMENTED` by a service without it. The option is available in every client (`WithKeep(false)` in Go, `keep=False` in Python, `keep: false` in Node and Java's `ParseOptions.withKeep(false)`, `SourcesOptions::keep` in Rust, and `keep` in Julia and MATLAB), and a one-document parse refuses it.
