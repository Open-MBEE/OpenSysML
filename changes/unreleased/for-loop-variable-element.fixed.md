- A `for` loop reflects its iteration variable again, once: the loop owns it first, through a `FeatureMembership`, as a `ReferenceUsage` with an `elementId` of its own (`A__n_ploopVariable`), so `ownedFeature` and `nestedReference` hold it and `ForLoopActionUsage::loopVariable`, which was not derived, answers it. A named loop node (`action n for i in 1..3 { }`) and an unnamed loop read the same.
- A feature chain through a `for` variable declared with a type (`for c : Component in components { perform c.run; }`) resolves through that type instead of reporting `no scope for member lookup in c`.
