- **An untyped feature valued by an invocation or a constructor is typed by the value's result for member lookup.** `action run = Base(x = 3, z = 7);` now resolves `run.r` to `Base::r`, so the model runs and reads `7`; `attribute c = mk();` reads the members of the calc's result and `part c = new Car();` those of `Car`. The rule is KerML `checkFeatureValuationSpecialization`: a feature with a value, no declared specialization and no direction specializes the value's result, so a `default` value, a directed feature or a `:>` feature is typed by its declaration alone, as the pilot has it.
