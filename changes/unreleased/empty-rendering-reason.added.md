- A rendering with nothing to draw says why. `opensysml/render` (and the gRPC and engine renderings) carry a notice for every result with no node, edge or row — the view exposes nothing, every element it exposes is rejected by its filter (naming the filter as written), what it exposes does not resolve or is nothing, nothing it exposes is shown by a rendering of this kind, or the view shows pictures alone — and, when the document has an error, its first error in the CLI's words (`<file> did not analyse cleanly; nothing was rendered: <line>:<col>: <message>`). The text and Mermaid forms end with the same reason, so a view whose filter rejects everything now reads `every element the view exposes is rejected by its filter @RequirementUsage; the rendering is empty` rather than `the view exposes nothing`. The VS Code diagram panel puts that reason in the status line and where the drawing would be, never an empty canvas (a layout without extent included), a table with no row lists the reasons in place of `No elements to list.`, and the extension logs every render with nothing to draw to the SysML v2 Output channel — every render while `opensysml.trace.server` is on — as the view, kind, node, edge and row counts and the notices.
