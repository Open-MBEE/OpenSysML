- A default run (`reverse`, `declared`) now reports its values only up to the partial order the Kernel Semantic Library fixes. Each choice point it records is classified by the lowered footprints the checker's reduction already uses: alternatives that write what another reads or writes, or meet on one channel, conflict; the rest commute and are marked `independent`. A value a conflicting alternative wrote prints with an order-dependence marker — `x = 1 (order-dependent; 2 choice points — explore shows the set)` — in the CLI `-action`/`-state` output, the REPL (`%action`, `%step`, `%continue`, `%advance`, feature display), the trace (`choice … ; order-dependent: x`) and the gRPC/Connect surfaces (`order_dependent` on `FeatureValue`, `ExecuteActionResponse` and `ExecuteStateResponse`; `order_dependent` and `independent` on a `choice-point` diagnostic, under the `order_dependence` capability), and in the Python (`ActionOutputs.order_dependent`, `Diagnostic.order_dependent`/`independent`) and Node (`orderDependent`, `ModelDiagnostic.orderDependent`/`independent`) clients. Values nothing order-dependent touched print as before. Conformance cases state the marker as `orderDependent`.
