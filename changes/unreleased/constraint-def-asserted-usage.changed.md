- **A SysML v1 owned rule migrates as the OMG mapping shapes it: a `constraint def` whose result is the specification, asserted by a usage typed by it.** `sysml -migrate` writes `constraint def 'Positive mass' { in ref context : Vehicle[1]; context.mass > 0 }` beside `assert constraint 'positive mass' : 'Positive mass' { in ref :>> context = this; }` in the constrained block, instead of one `assert constraint 'positive mass' { mass > 0 }`; the context parameter is written only when the specification reads the block's features. A rule of a constraint def, a behavior or an operation keeps the inline form, since no context parameter reaches their parameters, and a non-Boolean specification stays unmapped. The runtime's `this` inside an asserted constraint or requirement usage now names the object owning it, so `-validate=<object>` evaluates the migrated form; checked about no object (`-constraint` without a subject, as the MDK plugin verifies a v1 block's constraint), `this` denotes an exemplar of the type made from its declared defaults for the check and discarded with it.
