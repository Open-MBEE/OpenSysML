- **`install.sh --version nightly` no longer refuses the bundle it just downloaded.** The nightly workflow listed the four `opensysml-<platform>.tar.gz` bundles twice in `SHA256SUMS.txt` (the glob that appended the Python sdist matched them too), so the installer's digest lookup printed the digest twice and the comparison failed with `does not match SHA256SUMS.txt` on a correct download; every nightly since the clients' snapshots were first published was affected, on Linux and macOS, for any `--tools` selection that includes `sysml` or `sysml-lsp` (tagged releases, `--os windows`, `install.ps1` and the tools published on their own were not). The workflow now names the Python distributions exactly and checks, before signing, that the manifest lists every asset once and that each is present with the digest it names; `install.sh` and `install.ps1` count a line repeated verbatim once and refuse a manifest that lists an asset with more than one digest.
