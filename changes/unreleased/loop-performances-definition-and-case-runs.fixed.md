- A loop reached by an action definition run on its own, or by the body of a case, is now a performance its occurrence holds under `loops`, as a loop of an action usage already was (KerML 1.1 §8.4.4.7.2 `checkStepEnclosedPerformanceSpecialization`; `Actions::Action::loops`): the definition's occurrence is made when its first loop is reached, so `size(loops)` and `loops.body` no longer read empty there. A loop a body iteration reaches as a statement is held by that iteration (`loops.body.loops`), and the usages an unnamed loop body declares (`for i in xs { action add …; }`) are `subperformances` of each iteration, since the body is an action usage whether or not it is named (SysML.xtext `ActionBodyParameter`). An assertion such a run reaches reads the loops held by then, so `assert constraint { size(loops.body) == 3 }` ordered after a loop judges the iterations performed instead of reading none. Traces of such runs gain the `materialize:` lines of the occurrences now made. Loops of a calculation that is no case and of a constraint are still held under no object.
