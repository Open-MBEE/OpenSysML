- A type's inherited members are now derived as KerML 8.3.3.1.10 states them (`inheritedMemberships` = `removeRedefinedFeatures(inheritableMemberships(…))`), type by type from what its supertypes pass on. An alias of a redefined feature no longer resolves through an unnamed redefinition (`x.aa`, `B::aa` under `alias aa for a` and `:>> a`); an inherited feature that redefines what an owned feature directly redefines is removed with it (`C :> B { c :>> A::a; }` has no `b` where `B` declares `b :>> a`); a private redefinition, or one a supertype itself lost, removes nothing further down, so a feature another specialization still passes on resolves whichever general is listed first; and a `first s;` start marker no longer binds an inherited action its body redefines under another name.
