- OSLC Query text and the API `Query` answer a property no result row carries as absent again, as before they were translated into document-query plans: `oslc.select=sysml:body` (`select: ["body"]`) over a model without comments, a `where` or `oslc.orderBy` on such a property, and a `select` of `payloadArgument` over a model with an `accept` (whose `AcceptActionUsage::payloadArgument` OpenSysML does not derive yet) all answered a typed error instead. In the document-query engine, a property some metaclass declares is now absent on the rows lacking it rather than unknown, a `Project`, `WhereFeature` or `OrderBy` that tolerates absence treats an undeclared derivation as absent, and only a name no metaclass declares is the unknown-property error. An empty `select` reports every property but `elementId` again, `body`, `locale`, `language`, `satisfiedRequirement`, `satisfyingFeature` and the send arguments included; and `oslc.orderBy=-p` sorts the rows lacking `p` last, as the lexical evaluator did, rather than first.
