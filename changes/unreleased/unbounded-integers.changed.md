- **Integers are unbounded, as KerML's `ScalarValues::Integer` is.** An Integer result that leaves `int64` is promoted to an arbitrary-precision integer and demoted again when it fits, so `9223372036854775807 + 1` is `9223372036854775808`, `2**70` is `1180591620717411303424` and `(2**70) / (2**69) == 2` instead of an `arithmetic overflow`; values within `int64` keep the existing fast path. Equality, hashing, ordering, printing, quantities, ranges, collections, library functions, Monte Carlo, sweeps, the SMT/BMC engines and their replay, JSON, RDF, documents, serialized notation and the `sysml-engine` WebAssembly engine all carry the exact value. A result larger than the new Integer size budget (`OPENSYSML_MAX_INTEGER_BITS`, default 1048576 bits, at least 64 so every `int64` fits) is refused with `integer size limit exceeded` rather than hanging, and an Integer beyond `int64` used as an index, multiplicity bound, dimension or size is a typed error, since it addresses nothing. The wire adds `Value.big_int_value`, `Quantity.big_int_magnitude` and `DocumentValue.big_int_value` (decimal strings) for values beyond `int64` only, so existing clients see no change; the Go, Python, TypeScript, Rust, Java, Julia and MATLAB clients read and write them. `sysml -compile -target go` computes Integers exactly with `math/big`; `-target c` refuses a calc whose Integer arithmetic is not provably within `int64`, naming the construct.
