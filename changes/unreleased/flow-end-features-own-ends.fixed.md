- `GetElementProperties` now answers a flow's `sourceOutputFeature` and `targetInputFeature` with the features its two ends own — for `flow f from t.fuelOut to e.fuelIn;`, `f::source::fuelOut` and `f::target::fuelIn` — rather than the `Tank::fuelOut` and `Engine::fuelIn` those redefine, as KerML 8.3.4.9.2 `deriveFlowSourceOutputFeature` and `deriveFlowTargetInputFeature` state ("the first `ownedFeature` of the first/second `connectorEnd`"). Succession flows and KerML flows read the same way; a flow or message declaring no ends still answers none. The API-JSON element form (`sysml -convert api-json`) now writes the two properties with the same elements (#2199).
