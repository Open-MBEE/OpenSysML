- A feature its clause leaves nameless is now named, on reflection, RDF and API JSON alike, by the feature it implicitly redefines, as KerML derives `Feature::effectiveName`: a positional parameter (`in item;` under `action shoot : Shoot`) by its behavior's (`image`), a nameless objective by `obj`, a `return` parameter by `result`, and a connector or allocation end by the end it occupies (`logical`/`physical`, `source`/`target`). Element::name states the derived name, `declaredName` stays the written one, and `qualifiedName` is spelled under the owner's; an end keeps its name only, being positional in this mapping. A query result identifies such a feature by that name too (`Check::obj::r`), as the conversion writes it. A document of no recorded kind declaring only what KerML's keywords spell (`class`, `function`, …) and nothing SysML alone spells now reads as KerML, so a graph without its source text regenerates and re-reads under the same names.
