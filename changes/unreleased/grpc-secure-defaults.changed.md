- `sysml-grpc` binds loopback by default: `-port 50051` alone now serves `localhost:50051`, reachable only from the same machine, and the health server binds the same host. An address other machines reach (`-host 0.0.0.0`, a hostname of the machine) is served only with a bearer token — `-token-file`, `-token` or `OPENSYSML_GRPC_TOKEN` — that every call on every protocol must carry as `Authorization: Bearer` (grpc-go: the `authorization` metadata); a call without it is `unauthenticated` (HTTP 401). Starting non-loopback without a token fails at once. Anyone who relied on `-port` alone being reachable from another host passes `-host 0.0.0.0` plus a token, or `-host 0.0.0.0 -allow-unauthenticated` to keep serving every caller behind a proxy that authenticates on a trusted network; nothing implies the opt-out. The container image now runs `-host 0.0.0.0` and so needs `OPENSYSML_GRPC_TOKEN` (or a mounted `-token-file`) or the opt-out to start. `GET /health`, `-transport stdio`, `-exit-with-parent` and the private child a client starts for itself are unaffected.
- Every `sysml-grpc` call is logged on one line at `INFO` with the peer address, method, protocol, status code, duration and whether it was authenticated, on both transports; a refused call is logged at `WARN` with the peer. The token is never logged.
