- A transition's trigger, guard and effect now read reflectively as the `TransitionFeatureMembership`s the RDF/API JSON export and the pilot write. The trigger's `AcceptActionUsage` and the guard expression exist reflectively, and `TransitionUsage::triggerAction`, `guardExpression` and `effectAction` are derived. A time or change trigger's `TriggerInvocationExpression` is the accept's `payloadArgument`. Each `kind` is the library literal, so `kind == SysML::Systems::TransitionFeatureKind::guard` and `kind == SysML::Systems::TriggerKind::'when'` are `true` in `%eval`, metaobject reads, query cells, `WhereFeature` and gRPC `Evaluate`. Before this, the effect read as a plain `FeatureMembership` and the trigger and guard were missing.
