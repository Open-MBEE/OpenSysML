- **A workspace holds closed documents as their interface records, and hydrates them on demand.** A file whose bytes, library, conformance mode and record format match a record in the shared cache (`sysml-ls/libs` under the user cache directory) is opened as that record — its scopes and symbols without a tree, and the diagnostics its analysis found — and a file just analyzed by `sysml -validate`, `-satisfy`, a REPL load, or a save in the language server writes its record for the next run. A record installs only where its recorded analysis is still answered by the same documents unchanged; otherwise the file is parsed as before. Any request that needs a recorded document's body — a runtime or debugger over the workspace, references, rename, the hover's documentation, `%print`, the editor opening it — hydrates it first: parses it and invalidates what read it, exactly as an edit does; closing a document unchanged on disk demotes it to its record again. A record also carries the file's top-level member list, so a load from records is summarized as a load that parsed is. `-no-record-cache` on `sysml` and `sysml-lsp`, or `OPENSYSML_RECORD_CACHE=0`, holds every file loaded and writes no record.
