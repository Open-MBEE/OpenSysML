- An action written as an assignment, an `if`, a `while`/`loop` or a `for` loop subsets the feature of its kind (SysML v2 §8.4 Table 32: `Actions::Action::assignments`, `ifSubactions`, `whileLoops`, `forLoops`, or `Actions::assignmentActions`, `ifThenActions`, `ifThenElseActions`, `whileLoopActions`, `forLoopActions` outside an action) for every reader of the semantic model, and holds the parameters its notation states: `target` (with `startingAt` and `accessedFeature`) and `replacementValues`; `var`, `seq` and `body`; `whileTest`, `body` and `untilTest`; `ifTest`, `thenClause` and `elseClause`. So do a send action (`payload`, `sender`, `receiver`), an accept action (`payload`, `receiver`) and a terminate action (`terminatedOccurrence`). Each redefines the parameter of its kind (Table 33 `checkAssignmentActionUsageStartingAtRedefinition`, `AccessedFeatureRedefinition`, `ReferentRedefinition`, `checkForLoopActionUsageVarRedefinition`; KerML `checkFeatureParameterRedefinition`) and is featured by the snapshots of its action. Inheritance reads these: such an action no longer inherits, beside its own, the parameter of its kind it redefines, so a diagram no longer lists `^payload`, `^sender` and `^receiver` on a send action that states them. Readers of the semantic model, `GetElementProperties` among them, answer the name the redefinition gives such a parameter (`payload`, `seq`); element ids and the default export, which writes none of these parameters or relationships yet, are unchanged.
