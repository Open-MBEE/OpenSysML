- A state's `entry`, `do` and `exit` actions take an accept directly — `entry accept a : Sig via p;`, with a named or unnamed payload, `via`, and with or without a body (SysML v2 §8.2.2.18.1 `StateAcceptActionUsage`) — as the pilot does, where the parser reported `expected an action, an action reference or '{' after 'entry'` and a stray `expected the target of the transition after 'then'`. It is the `AcceptActionUsage` the `action accept …` spelling already was, so the symbol table, queries, the LSP, API JSON and Turtle see one under the `StateSubactionMembership`, where the export wrote a `PerformActionUsage` for either spelling. At run time an entry accept parks its state's entry until the occurrence arrives and the do behavior and the state's completion follow it, where the runtime ran it as an action of no content.
