- **The Jupyter kernel binds its channels in `Listen` and serves them in `Serve`; `Run` is the two in sequence.** A TCP channel whose port is 0 is bound on a free port and the connection `Listen` returns names the port taken, while a port given is bound as given, so a connection file keeps naming the ports Jupyter chose. The kernel's own tests used to reserve five free ports, release them and have the kernel bind them later; another process on a busy CI runner could take one in between, and the test then waited minutes on a dial the kernel would never answer. They now bind on port 0 and dial the ports `Listen` reports, and a kernel that fails to bind fails the test at once.
