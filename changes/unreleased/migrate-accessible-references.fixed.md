- **The SysML v1 migration writes references the v2 accessibility rules admit.** A reception's method reads the accepted signal's attributes through the accept that holds the payload (`receive.setLevel.value`, not `setLevel.value`, a sibling action's feature being reachable only by dot notation); an «Allocate» between two definitions, which no `allocate` can end on, is written as an `allocation def` whose two `end` features are typed by them; and a stereotype tag referring to a definition is written as the element cast to its metaclass (`owner = Acme meta SysML::PartDefinition;`), since a type is not a value. The reference implementation accepts each; before, it rejected them.
- **A block's activity that reads the block's features is written as an action usage of the block.** A `Run` whose body assigns an attribute, accepts a signal at a port, calls an operation of a part, or weighs a decision by a «Probability» property, is `action run { … }` on the `part def` (`perform action run { … }` for the classifier behavior), its body running on the object and reaching its features by their bare names — a definition nested in the block reaches none, so the reference implementation rejected `accept sig via rx`, `perform action x ::> motor.spin` and `p = bias` written in one. Calls, receptions, state behaviors, interactions, simulation configurations and Monte Carlo analyses name the usage (`perform action x ::> run;`), and an activity some call cannot reach a usage from — one whose target pin holds a parameter or a created object — stays an `action def`. An «Allocate» ending on such an activity's node is `allocate run.measure to probe;` in the part def when the activity is performed; one ending on a node of an `action def`, or of an `action` usage a call runs (a constant feature, which the part's variable `allocate` cannot relate), is a plain `dependency`, with the reason.
- **The checker reports a connector end and an annotation value that name a definition.** `allocate A to B` or `connect A to a` where `A` is a definition, and `@Org { owner = Acme; }` binding a `part def`, now report `Must be a valid feature`, as the reference implementation does; the checker was silent on both.
