- The unbounded value `*` is answered wherever the ordering KerML gives it decides the result, in the function notation as in the operator notation: `'>'(*, 1)`, `'=='(*, 1)` and the other comparison and equality functions, `max`, `min` and `abs` in every numeric library package (`max(*, 1)` is `*`, `min(*, 1)` is `1`, `abs(*)` is `*`), `ToString(*)` (`"*"`) and unary `+`, which the evaluator refused before while answering `* > 1`. Arithmetic over it (`+`, `-`, `*`, `/`, `%`, `**`, `^`, unary `-`, `..`, `sum`, `product`) is still an evaluation-time error naming the operation — the Kernel Function Library defines no result for it, and the pinned pilot leaves such expressions unevaluated — while the checker accepts the well-typed expression, as it accepts a division by zero. Beside a feature the model leaves open, the ordering stays open in both notations too (`u < *` was refused while `'<'(u, *)` was answered), and `max(*, u)` is `*` whatever `u` holds.
