- **A view whose only `Layout` is about a performer draws its whole flow again.** Placing a swimlane, which is what dragging a lane in the VS Code diagram panel saves in a view with no other `Layout`, made `sysml -render` leave every other node undrawn in the dot, mermaid, plantuml, d2 and drawio forms (`9 node(s) without a position, left undrawn`), while the panel went on drawing them. A swimlane frames the nodes of its performer, so swimlanes placed alone no longer count as positioning the drawing: the flow is laid out and drawn whole, the draw.io form draws the lane where its `Layout` says, at the stated size when it states one, with the flow drawn around it, and the forms that pin no position keep the `Layout` as a comment. A view that also places a node is drawn as before. Importing a draw.io file in which a swimlane was moved, in a view placing nothing else, now places every flow the file shows rather than the moved lane's flow alone, so the next render leaves no other flow undrawn. The same holds when a node is moved in a view whose only `Layout`s are about performers, and the placed lanes stay where their `Layout`s say. A flow holding a step with no name is the exception: only a `Layout` on the declaration could place that step, in every view, so the import leaves that flow unplaced and says so instead of changing other views. Flows drawn around lanes placed one under the other put their remaining steps beside the lanes when under them they would cover the other flow's lane.
