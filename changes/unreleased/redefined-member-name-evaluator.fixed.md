- A feature chain evaluated at runtime (`-e`, a feature value, a condition) resolves each member in the namespace of the feature before it, as the static read does: a feature a redefinition removed from that namespace (KerML §7.3.4.5, §8.3.3.1.10) is `unresolved reference: u has no member subj: U::s redefines it` instead of reading the value under the redefined name. This covers a written redefinition (`bus.own` beside `dry :>> own`) and a case role's (`u.subj` beside `subject s`, `u.obj` beside `objective o`); the redefining name and a name an unnamed redefinition takes (`objective { }` as `obj`) still read the one value.
- The static read of a member chain no longer resolves, through the usage's type, a name the usage's own redefinition removed: `a.x` for `part a : A { attribute y :>> x; }` is `unresolved member: x`, as `a::x` and `b.x` for a definition owning the redefinition already were; `attribute :>> x = 1;` keeps the name it takes.
