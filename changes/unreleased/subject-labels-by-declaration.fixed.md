- Every surface names an object a subsetting usage materializes by that usage. `%validate`, `-validate` (text and `-json`), gRPC `ValidateInstance` and the `Verdicts` document query labelled such an object by its position in the collection it subsets (`assembly.subsystem[1]`) while `%constraint`, `%requirement`, `%satisfy` and the gRPC verify RPCs named its declaration (`assembly.small`), and `%satisfy` over a subsetting collection dropped the index (`assembly.smalls` twice). One rule now spells every held object: the feature's name, indexed for a collection's element (`cheap[2]`), or the subsetting usage declaring it (`assembly.small`, `assembly.smalls[2]`) — the values of a subsetting feature are values of the subsetted one too (KerML §7.3.4.4) and a feature is unordered by default (SysML v2 §7.6.3), so the declaration, not a position, is the identity.
