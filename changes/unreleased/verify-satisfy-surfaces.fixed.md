- An objective's `verify r;` is no longer reported as a satisfaction assertion by `-satisfy`, `%satisfy` and gRPC `VerifySatisfaction`, which answered it `could not be evaluated` with no subject to read; the verification surfaces report it.
- A `satisfy r;` a definition states is checked model-wide (`-satisfy`, `%satisfy`, gRPC `VerifySatisfaction`) against every object of that definition the session or the service holds, one verdict per object as `-validate=` decides it, and asks for an object of the definition when none exists instead of failing on the requirement's subject (`no value for feature product`); one a usage states instantiates that usage, as `by` does.
- A verification objective stating only `verify r;` is satisfied — a requirement check over no constraints is true (`Requirements::RequirementConstraintCheck`) and `verify` records what the case verifies, not a condition — so the case is decided by its body's verdict and `-analysis` exits 0 for a passing case and 1 for a failing one; an objective whose own condition cannot be evaluated stays `undecided`.
