- `subsetting-constancy-conformance` now fires for SysML usages: a usage that may vary in time (owned by an occurrence definition or usage, not a portion, not a composite action — `Usage::mayTimeVary`) and subsets or redefines a `constant` usage or an end without being constant itself is an error, as `validateSubsettingConstantConformance` requires; before, only a KerML `var` feature was ever reported. The rule reads the subsetted feature's own constancy, so a variable feature subsetting a non-constant feature that itself subsets a constant one is no longer reported.
