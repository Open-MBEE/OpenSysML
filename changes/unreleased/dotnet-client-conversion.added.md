- The .NET client converts and migrates models and writes them to disk safely. `Connection.ConvertAsync` writes a model from a file, inline content or a parsed model as SysML or KerML notation, RDF Turtle or the SysML v2 API's JSON element form, with the source format, tolerated syntax errors, the id form, the documents of a multi-document model, the compact JSON form and the semantic check's diagnostics, answering a `Conversion` with the formats used, whether the mapping is experimental, and the standard-library elements an `api-json` conversion refers to as `LibraryReference`s, which `ConvertOptions.IncludeLibraryStubs` also writes as roots; `Model.ConvertAsync`, `ToNotationAsync`, `ToTurtleAsync`, `ToApiJsonAsync` and `SaveAsync` do so for a parsed model. `Connection.MigrateAsync` migrates a SysML v1 model (XMI, an Eclipse UML2 file or a `.mdzip` archive, from a file or as bytes) with an optional full report, the tool's stored results, an MTIP layout, an image base URL and strictness, answering a `Migration` whose `MigrationReport` accounts for every element and whose `MigrationFile`s are the images the model refers to. A conversion or migration the service could not make raises `ConversionException` or `MigrationException` keeping its formats and diagnostics, and sending a v1 model to conversion or a v2 model to migration is left to the service to refuse. `Conversion.SaveAsync`, `Model.SaveAsync` and `Migration.WriteAsync` never replace an existing file unless `SaveOptions.Overwrite` asks, write each file whole through a temporary file moved into place, remove what a failed or cancelled write created, never replace the v1 model a migration came from, and refuse with `UnwritableException`, before writing anything, a migration file that is absolute, names a drive or share, climbs out with `..`, is not a portable file name, lands on another file, or passes through a symbolic link. The conformance runner covers Convert and Migrate.
