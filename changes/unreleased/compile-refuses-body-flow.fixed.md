- `sysml -compile` (C and Go) no longer compiles a calc whose body is a token flow the compiled program cannot express, dropping the effect or reordering the steps: an `accept` in the body or in a loop or branch block (the compiled program answered where the interpreter waits for the message), a `perform` of an action, a flow between pins, a nested action stating how many times it is performed (`action a [2] {…}` ran once), and nested actions that successions order other than as they are declared (`first a then b` with `b` declared first ran `b` first) are each refused with a typed `UnsupportedError` naming the construct, as a `terminate` and an outside assignment already were; a `send` is refused by name too. Nested actions that only run statements in declaration order still compile.
