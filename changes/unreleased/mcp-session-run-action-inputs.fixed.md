- **`session_run` binds an action's inputs.** The `sysml-mcp` tool's `arguments` were read for a calc and an analysis case only; for `kind: action` they were dropped, so the action ran with its input parameters unbound and the verdict reported whatever that produced (a type mismatch in the body, typically) rather than the arguments' effect. The arguments now bind the action's `in` parameters as the runtime binds an invocation's: positionally in parameter order, or written `parameter=expression`, with an unknown parameter, a parameter bound twice and a wrong count each refused by name. The REPL session gains `RunActionWithInputs` beside `RunAction`; under `%engine check` or explore an action with arguments is unresolved, as those search every schedule from the action's own start. Run on an object that already performs the action, the arguments must be the bindings its performance holds (`in ref :>> context = this`, given as `context=<the object>`), as the ExecuteAction RPC requires; the comparison now reads a stored reference binding as the one-element sequence a bare pin holds, so the object itself passes where before only a not-yet-stored binding did.
