- **Instantiating a `ShapeItems::RightTriangularPrism` reports what is wrong once, where it lies, and nothing for what is merely unset.** The check `-instantiate` makes over a new object reported every feature value that failed to materialize, so one failing value was reported again for each feature reading through it — a prism given only its `height` printed five errors for two causes — and a value derived from an attribute nothing gives a value to (`xoffset = length / 2` over an unset `length`) was a finding while the unset attribute itself was not. A failure is now reported once, as the innermost feature value that failed, located by the usages walked to it (`in shape: feature value rf.width: cyclic feature value dependency: rf.width`); a value open for an unset feature is passed over as the unset feature is, and reading it is still the typed no-value error naming that feature. The two findings a fully dimensioned `RightTriangularPrism` still reports are the vendored library's own — `rf`'s `width = rf.width` is bound to itself, and `hypotenuse`'s `length = (length^2 + width^2)` writes an area to a `LengthValue` — recorded in `docs/project/omg-issues.md`.
