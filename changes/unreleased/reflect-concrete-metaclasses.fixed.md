- Reflection, API JSON and RDF now state the concrete metaclass the grammar gives four forms that used to reflect as their general class or not at all: a usage declared by prefix metadata alone (`#M x;`) is a plain `Usage` rather than a `ReferenceUsage` (composite unless written `ref`), a namespace's `filter` conditions are owned through `ElementFilterMembership`s, a `calc def`, `calc` or other function-like body's result through a `ResultExpressionMembership`, and the two ends of a `flow from a to b;` as `FlowEnd`s (named `source` and `target`; an end written `a.b` reference-subsets the feature it attaches to, a `message`'s events are no ends) through `EndFeatureMembership`s, so `ownedMembership`, `ownedMember`, `ownedFeature`, `ownedEndFeature` and the qvts `Elements_<Metaclass>` probes see them, and the element form's `@id` names a flow end and a filter condition as the conversion writes them. `ExhibitStateUsage`, `IncludeUseCaseUsage`, `LibraryPackage` and KerML `SuccessionFlow` are classified the same way whether parsed or restored from the library cache, and the grammar-to-metaclass map baseline is regenerated.
