- **Imports that make a namespace's memberships indistinguishable are reported.** Two imports bringing members of one name or short name whose metaclasses conform — `import A::*; import B::*;` where each package owns a `part def Engine`, or one recursive `import V::**` reaching two nested `vb` — now warn once per name on the import bringing the later membership, naming every colliding member and the import it came through: `Duplicate of imported member name 'Engine': A::Engine (import A::*), B::Engine (import B::*)` (code `name-conflict`, beside the owned and inherited duplicate-name warnings). An imported member repeating one the type inherits warns the same way (`Base::x (inherited)`). Resolution is unchanged and still takes the first membership. One membership two imports both reach, an alias beside the element it names, an imported name an owned member hides, a pair whose metaclasses are unrelated and the standard library's own members are not reported.
