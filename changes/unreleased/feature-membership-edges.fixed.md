- Tree and definition renderings draw a feature membership as the graphical notation does: from the owner to the usage's node, with a filled diamond at the owner for a composite usage and a hollow one for a non-composite usage — a `ref`, an attribute, a port nested in a part, an end, a directed or an enumeration usage — as the model derives `isComposite`, and the usage's typing as a `definition` edge of its own from the usage to its definition. A tree used to hang the usage off its owner by a bare containment line and draw an owner → definition edge labelled with the usage's name beside it, with the diamond read off the `ref` keyword alone; that labelled edge is now drawn only for a usage listed in a compartment row, where it is the only way to show the relationship. Inherited usages drawn under a part follow the same rule. The `references` compartment of a tree node lists the usages the model derives as non-composite.
