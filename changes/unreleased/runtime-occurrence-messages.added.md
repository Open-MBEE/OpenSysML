- The runtime performs an occurrence def or usage as the interaction its body states: `%occurrence <name>` (`Context.ExecuteOccurrence`) realizes each `message` between `event occurrence`s of its lifeline usages (`part`, `item`, `port`, `occurrence`, `individual`) as a transfer posted from the lifeline object holding the source event to the one holding the target event, in the order the `then` successions admit; at each event the actions its body states are performed once on the lifeline object and the constraints it asserts are checked there; a typed usage inherits its def's interaction, and an occurrence usage of a nested interaction is performed at its place with the outer lifelines of its names. The run trace records the sends and accepts, so `-run-render sequence` draws the run as the modelled sequence.
- The SysML v1 migrator spells an interaction parameter a call argument reads through the occurrence def (`in rpm[1] = 'Spin Up'::rpm`), which the bare name inside the perform's body would not reach.
