- The inherited-name conflict rule (`name-conflict`, `Duplicate of inherited member name`) now applies inside requirement, concern, viewpoint and case bodies, which it used to skip entirely: an ordinary member that reuses an inherited name there is reported, while a subject, actor, stakeholder or objective that redefines the inherited one by position (SysML v2 §7.21.2, §7.22.2) still is not, whatever either is named. A library feature that a member redefines is no longer inherited, so another member taking its name (`action mine :>> subactions; ref action subactions;`, or `ref subj` beside a declared subject) no longer draws the warning.
