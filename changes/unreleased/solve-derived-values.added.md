- The solver asserts a *derived* declared value — an expression over other features of the same element, `attribute volume : VolumeValue = height * width * length;` — as the defining equation of its variable, where it used to fix the value the evaluator derived or, when a feature it reads held nothing, leave the value free of its operands (so `%solve Box::Crate::fits` synthesised a `volume` with no relation to `height`, `width` and `length`). `%check`, `%solve`, `%configure` and the `solve` engine now choose the operands within their bounds and the derived value as the equation gives it, listed under `Defined by the model:`; `%explain` and an unsat `%solve` name the equation among the conflicting conditions as `defining equation: … declared by the model` at the declaration's position. A literal default stays a fixed value as before, a value the object has materialized is fixed as held, and a value read through another object is the value that object derives. An attribute typed by a datatype with no declared value (`attribute height : LengthValue;`) held by an object is now fixed to the value the object holds, where it was passed over as if it held an object.
