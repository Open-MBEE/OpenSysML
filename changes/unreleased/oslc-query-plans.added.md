- OSLC constructs that were refused are supported: scoped terms (`sysml:owner{sysml:name="x"}`) and nested `oslc.select` (`sysml:owner{sysml:name}`) read one property step into the related element, `oslc.select=*` projects every property the selected rows could name (their metaclasses' the evaluator serves, the evaluator's own, an object's declared features), leaving out a column no row carries, and `oslc.searchTerms` becomes `WhereText` over the projected text columns. The structured `Query` reads a one-step path the same way (`owner.name`).

- **Queries over the objects a session holds**: `rdf:type=elmt:<id>` in OSLC text, or an `@type` of `<urn:sysmlv2:element:id>` in the structured `Query` (the element IRI the RDF conversion writes), selects the held objects whose definition is that element — the rows `RunDocumentQuery` gives an `Objects` plan — each answered under its path (`Garage::car.wheels[2]`) in the new, additive `QueryResultElement.path` field with its features (`sysx:pressure`, `sysx:engine{sysx:power}` as `engine.power`) as properties, filtered, ordered and projected like elements. `rdf:type` with a metaclass keeps selecting declared elements. Query, REPL and MCP report the path; the request and response shapes are otherwise unchanged.

- A document query's unknown-property error now carries a `QueryOutcome` path failure whose frontier lists the properties the rows could have named — the features of object rows included — and the nearest spelling, on `WhereFeature`, `Project`, `OrderBy` and `WhereText` alike.
