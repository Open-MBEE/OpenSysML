- The Maven dependency cache saved on `develop` now holds what a test run resolves. `.github/workflows/maven-cache.yml` skipped the tests, and Surefire resolves its JUnit Platform provider and the JUnit launcher only when tests run, so every Java job still fetched 13 files from Maven Central; a merge-queue Magic MDK job failed when Central answered one of them, `surefire-junit-platform-3.6.1.pom`, as not found, which Maven does not retry. The workflow now runs the tests with their result ignored, deletes every `*.lastUpdated` marker of a failed download, and builds the three trees again offline, so an incomplete entry is not saved; the cache key also hashes the workflow, so a change to what it resolves saves a new entry. `tests/hygiene` holds the policy in place.
