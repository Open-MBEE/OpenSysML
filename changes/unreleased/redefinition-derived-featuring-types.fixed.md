- A redefinition is now checked against the featuring types KerML 1.1 derives for a feature (`deriveFeatureFeaturingType`: the declared `featured by` types, the owning type of a FeatureMembership or the snapshots of it for a variable feature, and the first chaining feature's) rather than the declared `featured by` types or the lexical owner alone. A feature of a classifier nested in a type can no longer redefine a feature the enclosing type inherits (`validateSubsettingFeaturingTypes`, `Feature::canAccess`), a feature `featured by` the type that owns the feature it redefines is no longer reported as having the same featuring types when its own owning type features it too, and `validateRedefinitionFeaturingTypes` compares the sets with `Base::Anything` included and a variable feature's read as its owning type, as the constraint is written.
