- A subsetting feature now contributes its values to the feature it subsets wherever it is declared, as KerML 1.1 §7.3.4.4 states with no restriction to one owner: a part nested under another usage of the object (`part frame { part beam : Sub :> subsystem; }`), at any depth and once per object of that usage; one naming a feature of a nested object by a chain (`part stowed : Sub :> tray.items;`); and a namespace usage naming a feature of another namespace usage's object (`part extra : Heavy :> rig.subsystem;`). A roll-up over the subsetted feature therefore sums over them, a `default` yields to them, more of them than the multiplicity admits is a multiplicity violation, and where the subsetted feature is bound explicitly the nested subsetter holds one of the bound values rather than an object of its own. Before, only a subsetting feature declared on the same object as the subsetted one contributed.
