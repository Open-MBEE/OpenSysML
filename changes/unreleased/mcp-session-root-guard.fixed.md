- **`sysml-mcp` session tools stay inside the workspace root on every path.** A `repl.Session` now takes a file guard (`SetFileGuard`) that every file it reads or writes must pass — the files `%load` and `%save` name, those a directory or glob expands to, and the dependencies found beside them (library roots excepted) — and `sysml-mcp` installs the workspace-root check on each session it opens. So a `%load` or `%save` sent through `repl_command`, or a directory load that walks to a symlink pointing out of the workspace, is refused like a typed `session_load`/`session_save` naming the file.
