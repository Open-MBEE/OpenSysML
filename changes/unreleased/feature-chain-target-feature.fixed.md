- Reflective reads of an expression's references — `FeatureChainExpression::targetFeature`, `FeatureReferenceExpression::referent`, an invocation's `function` and the `Membership` the expression owns to name it — now resolve the name on demand when the resolver has not walked the document, as the gRPC service and the REPL build their models. Before, `last(consume::power.metadata).ownedRelationship.value.targetFeature` answered `[]` for `in power = powerPort.power;` and for the chain operand of `powerPort.power * 2.0`, and the expression owned no `Membership`; the API JSON export, which resolves every reference up front, already wrote the target (KerML 1.1 Beta 2 §8.3.4.8.4 `deriveFeatureChainExpressionTargetFeature`).
