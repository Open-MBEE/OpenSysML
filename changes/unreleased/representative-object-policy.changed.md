- The compliance map states the representative-object policy for a feature that states and inherits no multiplicity: the specification bounds the number of values a feature may hold (KerML 1.1 §7.4.12, §7.4.5.2; SysML v2 §7.6.3) and leaves open what a representative instance materializes for a valueless feature, so OpenSysML materializes one representative object for such a feature, none for a declared `[0..*]`, and judges no count against the defaulted feature; recorded as a tool decision. The rows that still described that one object as an assumed `1..1` of the specification now cite this policy instead, and the write-conformance row records that a write of several values to such a feature is held on the performing object but still refused when the running action itself declares the feature.
