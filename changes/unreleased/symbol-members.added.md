- `GetSymbol` now enumerates every member an element has (KerML 1.1 §8.3.3.1 `Type::member`) in `SymbolInfo.members`: the owned members in declaration order — `child_ids` stays those — then the inherited ones in inheritance order, each with its kind, whether it is inherited and the type declaring it; a redefinition masks what it redefines and a private member of a supertype is not inherited. Members inherited from standard-library content are withheld and counted in `withheld_library_members` unless `GetSymbolRequest.include_library_members` lists them, each marked `library`. Advertised as the `symbol_members` capability. The Python client's `Symbol.members(kind, inherited, library)` reads it, and `children()`, `parts()`, `ports()`, `bindings()`, `connections()` and `attributes()` are filters over it, so they agree: own members by default, inherited ones with `inherited=True`, each reporting `inherited` and `inherited_from`; `attributes()` keeps including inherited attributes by default and no longer walks the specialization chain client-side.
