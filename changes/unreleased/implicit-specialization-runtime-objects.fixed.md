- **Every performance the run creates carries the implicit specializations of its kind (KerML §7.3.4).** A loop's `enclosedPerformances` and `timeEnclosedOccurrences` now list its iteration bodies (not its `subperformances`/`suboccurrences`: `LoopAction::body` is not composite), a `ref action` in a behavior is one of its `enclosedPerformances`, a state's `entry`/`do`/`exit` action is the state's `entryAction`/`doAction`/`exitAction` rather than a second performance, and the Geometry library's `subitems` hold the faces, edges and vertices the library declares.
- **A `ref use case` written in a body is a reference usage.** The body-member parser only applied a `ref` before a one-word kind keyword, so `part def A { ref use case x; }` declared a composite use case (and so one of the part's `ownedActions`, forbidding it `nonunique`); the top-level form already kept the `ref`. A non-composite action, calculation, case or state nested in a part, item or port now implicitly subsets nothing, as in the pilot, and the SysML v1 migrator writes `nonunique` on such a reference where the checker accepts it, judging a v1 «Viewpoint» by the `view def` it writes.
- **A state's `entryAction`/`doAction`/`exitAction` stays resolvable beside the `entry`/`do`/`exit` action that redefines it.** The role redefinition of a library feature (a state action, a view's `render`) identifies the two at run time (`sm.entryAction == sm.en`) without masking the library name, as in the pilot; a written `:>>` and a case role (`subject`, `objective`) mask as before.
