- **The nightly VS Code extension is versioned as a development build of the release it leads to.** The snapshot's `opensysml-sysml.vsix` carried the extension manifest's version — the release already made — with the night as its pre-release part (`0.10.1-nightly-20261019-e8607989d`), which SemVer ranks *below* the released `0.10.1`, so VS Code offered the release as an upgrade from every night after it and a night never read as newer than the release it built on. The vsix now carries the same development version the Python and npm snapshots do, `0.10.2-nightly-20261019-e8607989d`: every night ranks above the release it builds on and below the one it leads to, and the workflow still refuses a vsix whose stamped version is not the one it publishes.
