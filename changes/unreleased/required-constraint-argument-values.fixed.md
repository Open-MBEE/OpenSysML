- A requirement that requires a constraint usage of its subject (`subject b : Budget; require b.closes;`) is checked with the arguments that usage states again. Since the bound-input rule for a performed action subsetting a valued usage, a value written on a parameter of the subsetted usage was dropped from the object's slot altogether, so `in demand = estimate` reached the constraint's condition unvalued and `demand * 1.25` failed with "operator '*' is not defined for a sequence and a Rational". The slot now holds the usage's value unless a holder of the object binds the parameter, which is all the bound-input rule needs.
