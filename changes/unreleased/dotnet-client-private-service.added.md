- The .NET client starts a private `sysml-grpc` when no service is named: `Connection.OpenAsync()` finds the binary `ConnectionOptions.BinaryPath` or `OPENSYSML_GRPC_BINARY` names, else `~/.opensysml/bin/sysml-grpc`, else the first on `PATH`, hashes it (`ExpectedBinarySha256` requires a digest), and starts it on a port the kernel chooses, as a child that exits with the process however the process ends. Connections that agree on the binary, its contents, `StartupTimeout`, `ShutdownTimeout` and `Version` share one service, which the last to close stops; `IsolatedService` gives a connection its own, and `Connection.StopSharedServicesAsync` stops every shared one. A service that exits on its own is not restarted: its connections fail with `TransportException`, and the next open starts another. New failures: `BinaryNotFoundException` listing every place looked at, `ChecksumMismatchException`, `UnsupportedPlatformException` and `ServiceStopException`. Releases are not downloaded. The Vehicle sample also runs against a private service.
- Private binary resolution follows symbolic links before parent-directory components, including in link targets. Shared shutdown reports failures from stops already underway in a read-only failure collection, and unloading stops children that finish starting after cancellation.
- A private service is started without `OPENSYSML_GRPC_TOKEN` in its environment (under any case of the name on Windows), so a token set for a remote service is never one the private child demands.
