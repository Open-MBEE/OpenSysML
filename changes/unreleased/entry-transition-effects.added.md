- **Transitions out of a named entry action run effects and routes.** `entry action boot; transition boot do { … } then s;` runs its effect after the entry action and before `s` is entered, and may target a junction or choice of the same body, whose route is resolved after the entry action; availability checks only the incoming transition's own route, and a dead nested default-entry junction fails with a typed run error when its separate entry transition is taken. In a region of a parallel state the effect, like a compound transition's segment effect inside the region it enters, interleaves with the sibling regions' entries, and `-schedule explore` reaches every order. A trigger on such a transition, or an effect on the shorthand `entry; then s;`, is still rejected.
