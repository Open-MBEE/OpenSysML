- The constraint solver now reads a feature's multiplicity as the model computes it: a stated, redefinition-inherited or implicit `[1..1]` (SysML v2 §7.6.3) multiplicity that admits several values refuses the read as before, and a feature that declares and inherits none, which the usual default `0..*` governs (KerML 1.1 §7.4.12, §7.4.5.2), is read as one value under an assumption the query records (`Query.AssumedOne`) and `%check`, `%solve`, `%explain`, `%configure` and `%optimize` print, instead of being taken for exactly one value silently. No count is asserted for it. A `%check` of a part walks a defaulted object-holding feature through its one representative object, as validation does, and reports the same assumption. The solve differential runs over the `.kerml` conformance cases too.
