- **A migrated operation call runs on the object its target pin holds, and send object actions are migrated.** A `CallOperationAction` whose target pin is fed by an object not read from `this` — an activity parameter, a fork, another action's output — was written as an action typed by the operation's action def running in the caller's context; it is now written with the target pin as a parameter typed by the class owning the operation, to which the operation's `context` is bound (`action n : Owner::Op { in ref :>> context = target; in target : Owner[1]; }`), and the flow into the pin is written, so the call runs on the object the pin holds. A call whose target is an object a `CreateObjectAction` creates acts on an empty pin, since `CreateObjectAction` is not migrated; the migration report says so. A `SendObjectAction` is now written `send request to target;` (or `via` its port), sending the object its request pin holds. A `StartObjectBehaviorAction` or `StartClassifierBehaviorAction` stays a placeholder keeping its pins, its note saying that a v2 object's behaviors start when the object does. The transformation census records the call operation and send object mappings as faithful and the two start mappings as a deliberate divergence, with candidate errata for the output pin's feature chain and for the send object mapping typing the sent item by its request pin.
