- `.github/workflows/wasm-cache.yml` now saves only the Go build cache entries the WebAssembly gate used. Each develop push restored the previous entry whole and saved it again with the objects of every package the push changed, so it had grown from some 2 GB to 5.7 GB within a day and took up to three and a half minutes to restore in every `WebAssembly gate` job. The pruning (`scripts/ci-go-build-cache.sh`) runs only after a gate that passed: a failed gate saves its cache whole for the next passing one to prune, and a run that never reached the gate saves nothing, so neither can replace the warm entry with a smaller one.
