- A `case`, `use case`, `view`, `viewpoint`, `concern`, `rendering`, `enum`, `satisfy requirement` or `include use case` usage a definition owns is a feature of its objects: reading it on an instance answers the nested object (or the enumeration literal) instead of refusing the member, and the standard library's collections of those kinds (`Case::subcases`, `UseCase::includedUseCases`, `View::subviews`, `Viewpoint::concerns`, `Rendering::subrenderings`, …) read on any object. An untyped one with no body (`view sketch;`) materializes an object like an untyped `part`, validating the owner visits the assertions those objects state, and `all` over their definition enumerates them.
