- **The v1 migration report says where a run will stop on a construct the tool simulated and v2 cannot run as written.** A state's entry or exit behavior, or a transition effect, whose activity waits for the clock (a duration constraint on one of its nodes, an accept of a time event, or a call of an activity that has one) is reported as an approximation naming the wait, since a v2 entry, exit or effect is performed whole at the instant it is triggered. A trigger or accept of a signal that no send action of the model sends and only a button of the tool's UI prototype posts is reported as waiting for a message nothing in the model posts, and a «SimulationConfig» whose `UI` names a prototype frame is reported as taking no input from it. A script body that reads a property declaring no default before it assigns it is reported as an approximation naming the property: in v2 the property holds no value until assigned, so a run reaching the read first stops, where the tool's script engine reads null and its arithmetic takes 0.
