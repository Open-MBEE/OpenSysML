- `%check`, `%solve`, `%explain` and `%configure` now derive a value declared through a chain rooted in one of the element's own features when no object is held for the root — `attribute :>> ok = s.amount > 2.0 and s.amount < 1.0;` over a requirement's subject `s`, a parameter of it (SysML v2 §7.21.2), asserts `ok == s.amount > 2.0 and s.amount < 1.0` as the defining equation (KerML 1.1 §7.3.4.5), so the requirement answers `unsat` as one stating the condition directly does, where `ok` was left free and the requirement answered `sat`. A chain whose root an object is held for is still read through that object, and a qualified or imported name still fixes the value the evaluator derives.
