- A declaration written with a keyword only the KerML grammar spells — `connector`, `class`, `struct`, `datatype`, `classifier`, `subclassifier`, `feature`, `step`, `expr`, `bool`, `behavior`, `function`, `predicate`, `metaclass`, `assoc`, `assoc struct`, `interaction`, `inv`, `multiplicity` — is now a `kerml-notation` **error** in a `.sysml` file by default, where it was a warning that only `-strict` made an error. SysML v2 §8.2.2.1.2 gives SysML its own reserved keywords and the SysML grammar has no production for these declarations, so such a file does not conform. Like every notation error it stops no later check: the declaration is still parsed, `sysml -validate` goes on to check the model and reports that the notation does not conform, and the message names the SysML spelling to write instead. A `.kerml` file is unaffected, and `typed by` and the KerML relationship clauses stay warnings by default.
