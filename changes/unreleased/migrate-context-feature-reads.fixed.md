- **The v1→v2 migration no longer writes `this.<feature>` inside behavior definitions.** In SysML v2 `this` denotes the definition's own occurrence, so the emitted code was unresolvable. A block-owned definition whose body needs its owner now gains an appended `in ref context : <Block>;` parameter and reads `context.<feature>` (`assign context.level := value;`, `via context.tx`, `p = context.bias`, `::> context.motor.spin`); usages owned by the block keep reading features lexically (`assign level := value;`), and every call site binds the parameter inside its own body as `in ref :>> context = <expr>;` instead of a `bind` statement. `this.<feature>` inside a definition now resolves against the definition's own occurrence, matching the standard's `Occurrence::this` semantics.
- **Positional invocation of an action with a trailing `in ref` context parameter now binds the performer.** `InvokeOperationWith` normalizes positional arguments to named before seeding the implicit reference binding, so `obj.nudge(delta)` runs instead of failing `no argument for context`; a redefinition binding a reference parameter to an instance of an unrelated type now fails the declaration check rather than slipping through, and `this` read as a value inside an action- or state-definition body statement denotes the definition's own occurrence rather than erroring.
