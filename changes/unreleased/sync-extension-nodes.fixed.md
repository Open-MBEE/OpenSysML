- `sysml -sync-diff` and `-sync-apply` against a SysML v2 API endpoint now decide every node typed outside the SysML vocabulary before anything is sent, not only a `sysx:Note`. A node of a class the repository has no metaclass for that no kept `sysml:` property references is left out of the comparison and reported as not carried under its class, as the note was; an element of such a class that a kept property does reference — a `choice` or `junction` pseudostate (`sysx:Pseudostate`), an `action a { … }` node (`sysx:ActionExecutionNode`) — is refused with the element, its class and the referencing property (`reposync.UnheldReferenceError`), where before the whole commit failed at the API with "the element has no single SysML metaclass" after the dry run had reported it as a create. An element stating such a class beside its SysML metaclass keeps its place, the extra class reported as not carried, and one stating two SysML metaclasses is refused by the diff (`reposync.AmbiguousMetaclassError`) rather than by the API. The repository's representation now states which classes it holds (`reposync.Carrier.Holds`), so a diff never writes a reference to an element the repository never receives. See `docs/reference/cli.md` (`-sync-diff`).
