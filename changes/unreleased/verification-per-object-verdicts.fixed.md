- A verification case a definition owns now runs once on every object of the definition a report is about, so the objects a multiplicity repeats (`part cheap : Definition [2]`, the members of a `[0..*]` collection, a part nested inside a repeated part) each get their own run and verdict on `%requirement`/`-requirement`, `%satisfy`/`-satisfy`, `-validate -json`, the gRPC verification reports and the document `verdicts` query; a definition's `satisfy` without `by` is likewise decided once per repeated object. Before, the walk that resolves a check's subject — one object per declaration, so a check naming a constraint inside `part wheels : Wheel[4]` is about one subject — also enumerated the objects a case runs on, and reported one verdict per usage. That subject resolution is unchanged.
