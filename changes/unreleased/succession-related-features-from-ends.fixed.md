- A succession's `relatedFeature`, `sourceFeature` and `targetFeature` are read from the two end features it owns, as KerML 1.1 §8.3.4.5.3 derives them, for every `then` form of an action or state body and for a transition's own succession. An action body's two-ended `first a then b;` is a `SuccessionAsUsage` the action owns, with two `EndFeatureMembership`s whose ends each own the `ReferenceSubsetting` of the feature written; a bare `assign`, `terminate` or `perform` statement is the action usage the successions around it relate, where `relatedFeature` was unanswered. A succession beside a bare `if`, `while` or `for` statement, or with an end written as a feature chain (`first a then b.c;`), still leaves it unanswered.
