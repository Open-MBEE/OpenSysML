- A connector's `relatedFeature`, `sourceFeature` and `targetFeature` are now the features its ends' reference subsettings reference, as KerML 1.1 §8.3.4.5.3 derives them: for an end written as a feature chain (`connect a.p to b.q`, `interface supplier ::> powertrain.tank.fuelOut`) that is the anonymous chain Feature the chain denotes as a whole, whose `chainingFeature` is the path, never the chain's last link — on every connector kind (connection, interface, binding, allocation and succession usages, KerML connectors), in reflection, in the API element form and in Turtle, where the chained ends were stated as nothing before. The Symbol facts of a connector list its ends and the features they connect (`connector_ends`; a connector end's own facts carry a `references` specialization with the chain's features), queries select `relatedFeature`, `sourceFeature`, `targetFeature` and an end's `referencedFeature`, and reflective evaluation hands the anonymous chain Feature back as a metaobject carrying its `chaining_feature_ids`, so `connectorEnd#(1).ownedReferenceSubsetting.referencedFeature` is a value rather than an unsupported one (#1956, #1957, #1958).
